# PYQT上位机主要工作

* 全局视觉定位（识别车模位置）
* 游戏逻辑运算（推箱子规则）
* 游戏画面生成（显示给车载摄像头看）
* 投屏服务（将画面传到车模上的手机）

# 各模块详解

## 1️⃣ mapper.py - 视觉定位模块
```md
# 当前角色（Demo 阶段）
作用：识别绿色控制块，模拟车模移动
方法：手动移动绿色块 → 识别位置 → 更新游戏

# 最终角色（比赛阶段）
作用：识别车模顶部标识牌（ArUco 码）
输入：全局摄像头俯视画面
输出：车模位置 (x, y) 和方向 θ
技术：OpenCV ArUco 检测 / 颜色识别
```

关键参数（当前）

```py
BLUE_LOW/HIGH    # 蓝色边框识别（定义游戏区域）
GREEN_LOW/HIGH   # 绿色块识别（模拟车模）
GRID_ROWS = 10   # 将场地划分为 10×10 网格
GRID_COLS = 10   # 对应游戏的 10×10 地图
```

工作流程

```py
def update(self):
    1. 读取摄像头画面
    2. 识别蓝色矩形框（游戏区域边界）
    3. 在蓝框内识别绿色块（当前）/ ArUco码（未来）
    4. 计算在 10×10 网格中的位置
    5. 返回网格坐标 (row, col)
```

## 2️⃣ virtual_world.py - 游戏引擎

```py
# 角色：推箱子游戏的大脑
功能：
  ✅ 管理游戏状态（玩家位置、箱子位置）
  ✅ 处理推箱子逻辑
  ✅ 碰撞检测
  ✅ 胜利判定

# 这个模块完全符合比赛要求！
```

核心方法

```py
create_boxes()          # 随机生成箱子
update(new_position)    # 更新车模位置（接收 Mapper 的输出）
try_move()              # 推箱子逻辑
check_win()             # 检查是否完成（箱子全部出界）
```

推箱子逻辑

```py
规则：
1. 车模移动到箱子位置 → 触发推箱子
2. 计算推动方向（基于车模移动方向）
3. 检查箱子新位置是否合法（不能出界、不能撞其他箱子）
4. 推动成功 → 箱子移动
5. 推动失败 → 车模退回原位

胜利条件：
所有箱子都被推到边界外（坐标 0 或 9）
```

## 3️⃣ game_window.py - 游戏画面

```py
# 角色：游戏的"显示器"
作用：将游戏状态转换为可视化画面
重要性：⭐⭐⭐ 这个画面是给车载摄像头看的！

# 为什么重要？
车载摄像头通过拍摄这个画面来"看懂"游戏：
- 红色圆球 = 车模自己的位置
- 棕色方块 = 需要推的箱子
- 边界 = 目标区域
```
绘制内容

```py
paintEvent():
    1. 绘制 10×10 网格背景
    2. 边界用特殊颜色（浅蓝色）
    3. 绘制箱子（棕色方块）
    4. 绘制玩家（红色圆球）= 车模位置
```

为车载识别优化

```py
颜色选择：
- 红色 (255, 80, 80)  # 高饱和度，易识别
- 棕色 (160, 100, 40) # 与红色色差大
- 蓝色边界           # 标识游戏区域

大小合适：
- 400×400 像素
- 每格 40×40 像素
- 手机屏幕显示清晰
- 车载摄像头可拍摄
```

## 4️⃣ screen_cast.py - 投屏服务

```py
# 角色：游戏画面的"传输通道"
作用：将游戏画面投屏到车模上的手机
技术：Flask Web 服务器 + MJPEG 流
重要性：⭐⭐⭐ 关键技术！

# 为什么需要投屏？
因为车载摄像头需要看到游戏画面！
手机 = 车载摄像头的"屏幕"
```

工作原理

```py
1. capture_widget()    # 截取 GameWindow 的画面
2. 转换为 JPEG 格式   # 压缩，quality=85
3. Flask 服务器       # 端口 5000
4. MJPEG 流传输       # 持续推送帧
5. 手机浏览器接收     # 显示实时画面
6. 车载摄像头拍摄     # 识别游戏元素
```

性能参数

```py
帧率：~30fps         # 足够流畅
质量：85%           # 平衡画质和传输速度
延迟：<100ms        # 实时性好
带宽：~500KB/s      # WiFi 轻松承载
```

```py
# 角色：整个系统的"指挥中心"
作用：协调所有模块，维持主循环
```

主循环（60fps）

```py
def loop(self):
    # 1. 视觉定位
    self.mapper.update()              # 识别车模位置
    pos = self.mapper.get_pos()       # 获取网格坐标
    
    # 2. 游戏逻辑
    self.virtual_world.update(pos)    # 更新游戏状态
    
    # 3. 画面更新
    self.game_ui.set_player_position(...) # 更新显示
    self.game_ui.set_boxes(...)           # 更新箱子
    
    # 4. 投屏传输
    self.screen_caster.update_frame() # 推送画面到手机
    
    # 5. 胜利检测
    if self.virtual_world.check_win():
        self.virtual_world.begin_game() # 重新开始
```

模块整合
```py
self.mapper           # 视觉模块

# 所有模块通过 MainWindow 协同工作
```

# 当前问题

1. 上位机根据实际情况对推箱子游戏的更新延迟还是大。
2. 推箱子游戏在运行时，如果车模标识牌速度过快，会一瞬间运动到很远的位置，然后才回到正确位置，但期间箱子貌似也会被这个异常所推动。
3. 针对格子的区分貌似不正确，车模位置与实际所处的方块位置有偏差。

# 优化思路

1. 针对视觉定位，摄像头画面只处理蓝布及蓝布周围一格范围内的区域，减少计算量，提高识别速度。
2. 增加车模位置的平滑处理，避免瞬间跳动过大。
3. 优化格子位置的计算方法，确保车模位置与实际方块位置一致。
4. 针对推箱子逻辑，增加异常检测，避免因车模位置异常导致箱子被错误推动。
5. 优化投屏服务的传输效率，减少延迟，提高实时性。
