# 毕设题目：基于STM32的小区火灾报警系统的设计与实现

## 一、内容要求

1. 火灾检测:温度传感器，烟雾传感器，红外火焰传感器:0-1m 火焰有效识别
2. 实时阈值判断与联动:任一参数超阈值，3s内触发声光报警;同步启动通风/喷淋继电器
3. 声光报警装置:蜂鸣器+LED警示灯
4. 本地显示:OLED 实时刷新温度、烟雾、火焰等传感器数据值，界面简洁直观
5. 远程通信:ESP8266 Wi-Fi模块，MQTT 协议上传数据到云端或微信小程序，报警信息同步推送至住户手机(短信/微信)
6. 分区定位报警:系统带房号/楼层信息，云端可显示具体住户位置，便于物业快速处置
7. 数据记录与追溯:TF 卡本地存储事件时间、参数值，支持USB 导出历史数据用于事故分析

# 具体实现

### **1. 系统总体设计**

#### **1.1 系统设计目标**

本系统旨在实现以下核心功能：
- **实时监测**：7x24小时不间断采集温度、烟雾浓度、火焰信号。
- **智能判断**：根据多传感器数据综合判断火情，降低误报率。
- **快速响应**：任一关键指标超阈值后，在3秒内触发本地和远程报警。
- **联动控制**：报警时自动启动风扇、水泵等外设。
- **多维报警**：集成本地声光报警、云端平台记录、移动端消息推送于一体。
- **数据可视化与追溯**：通过OLED屏和移动端实时显示数据，利用TF卡和云平台存储历史记录。

#### **1.2 系统架构**

本系统采用典型的物联网三层架构：感知层、网络层和应用层。

```mermaid
graph TD
    subgraph 感知层 (Perception Layer)
        A1[温度传感器 DS18B20]
        A2[烟雾传感器 MQ-2]
        A3[火焰传感器]
        A4[OLED显示屏]
        A5[蜂鸣器/LED]
        A6[继电器]
        A7[TF卡模块]
    end

    subgraph 网络层 (Network Layer)
        B[ESP32-S3 主控]
    end

    subgraph 应用层 (Application Layer)
        C[云端物联网平台 (MQTT Broker)]
        D[PC端监控后台]
        E[移动端APP/小程序]
    end

    A1 & A2 & A3 --> B
    B --> A4 & A5 & A6 & A7
    B -- Wi-Fi/MQTT --> C
    C -- API/WebSocket --> D
    C -- 消息推送/API --> E
```
- **感知层**：由各类传感器、执行器和人机交互设备组成，负责原始数据采集和本地指令执行。
- **网络层**：核心是ESP32-S3主控芯片，它处理感知层数据，执行本地逻辑，并通过内置Wi-Fi模块，使用MQTT协议与云平台进行双向通信。
- **应用层**：包括云端物联网平台和用户客户端（PC/移动端）。云平台负责数据接收、存储、分析、规则处理和指令下发；客户端为用户提供远程监控和管理界面。

### **2. 系统硬件设计与实现**

#### **2.1 硬件模块选型**

| 类别 | 模块名称 | 型号/规格 | 选型理由 |
| :--- | :--- | :--- | :--- |
| **主控**        | 微控制器 | ESP32-S3 | 高性能双核处理器，内置Wi-Fi，丰富的GPIO、ADC、I2C、SPI接口，满足所有外设连接和通信需求，性价比高。 |
| **传感器** | 温度传感器 | DS18B20 | 数字信号输出，精度高，抗干扰能力强，采用单总线协议，节省IO口。 |
| | 烟雾传感器 | MQ-2 | 对多种可燃气体和烟雾灵敏度高，提供模拟和数字两种输出，便于阈值判断和浓度量化。 |
| | 火焰传感器 | 红外火焰传感器 | 对760nm-1100nm波长的火焰光谱敏感，探测角度广，响应迅速，可有效识别明火。 |
| **报警装置** | 声光报警 | 有源蜂鸣器/高亮LED | 驱动简单，声音响亮，灯光醒目，能提供有效的本地警示。 |
| **执行器** | 继电器模块 | 5V 1路继电器 | 光耦隔离，驱动能力强，安全可靠，用于控制220V交流设备（如风扇、水泵）。 |
| **显示** | 本地显示屏 | 0.96寸 OLED | I2C接口，功耗低，自发光，对比度高，可在各种光线环境下清晰显示数据。 |
| **存储** | 数据记录 | TF卡读写模块 | SPI接口，通用性强，支持大容量存储，可方便地记录大量历史数据用于分析。 |
| **电源** | 供电模块 | AMS1117-3.3 | 经典的LDO稳压芯片，能将外部5V电源稳定转换为ESP32-S3及各模块所需的3.3V。 |

#### **2.2 硬件连接**

- **主控核心**：ESP32-S3开发板。
- **电源**：使用USB 5V供电，通过板载或外接的AMS1117-3.3模块为各3.3V设备供电。
- **传感器连接**：
    - **DS18B20** (DATA) -> ESP32-S3 (GPIO4)
    - **MQ-2** (AO) -> ESP32-S3 (ADC1_CH0 / GPIO1)
    - **火焰传感器** (DO) -> ESP32-S3 (GPIO2)，用于中断检测；(AO) -> ESP32-S3 (ADC1_CH1 / GPIO3)，用于强度读取。
- **输出设备连接**：
    - **OLED** (SCL, SDA) -> ESP32-S3 (GPIO5, GPIO6) (I2C)
    - **有源蜂鸣器** (I/O) -> ESP32-S3 (GPIO10)
    - **LED** (+) -> ESP32-S3 (GPIO11)
    - **继电器** (IN) -> ESP32-S3 (GPIO12)
- **存储模块连接**：
    - **TF卡模块** (CS, SCK, MISO, MOSI) -> ESP32-S3 (GPIO13, GPIO14, GPIO15, GPIO16) (SPI)

#### **2.3 PCB 设计与实现**

为了将系统从实验性的杜邦线连接转变为一个稳定、可靠的集成化产品，进行了PCB（Printed Circuit Board，印刷电路板）的设计与制作。这不仅能减小设备体积，还能显著提高系统的抗干扰能力和长期运行的稳定性。设计流程如下：

1.  **原理图设计 (Schematic Design)**
    *   **工具选择**：使用 Altium Designer、KiCad 或 EasyEDA 等专业的EDA（电子设计自动化）软件。
    *   **绘制过程**：根据2.2节的硬件连接方案，在软件中绘制详细的电路原理图。这包括放置ESP32-S3主控模块、各个传感器接口、电源稳压电路（AMS1117）、报警单元、存储模块和外部接线端子等所有元器件的符号，并完成电气连接。
    *   **封装关联**：为原理图中的每个元器件选择或创建对应的PCB封装（Footprint），确保电气符号与实际物理尺寸相匹配。

2.  **PCB布局与布线 (Layout & Routing)**
    *   **布局 (Placement)**：在确定PCB板框尺寸后，将元器件封装合理地放置在电路板上。布局时需考虑信号流向、高频与模拟信号隔离、散热以及外部接口的位置等因素。
    *   **布线 (Routing)**：连接所有元器件的引脚。关键信号线（如SPI时钟线）应尽量短而直；电源线和地线应足够宽以承载电流；推荐采用大面积覆铜作为地平面（GND Plane），以增强抗干扰能力。
    *   **设计规则检查 (DRC)**：完成布线后，运行DRC功能，检查是否存在短路、开路、线间距过小等不符合制造工艺要求的问题，并进行修正。

3.  **生产文件生成与制板**
    *   **Gerber文件生成**：将最终确认无误的PCB设计文件导出为Gerber格式的生产文件。Gerber文件包含了电路板各层的图形数据（如铜层、阻焊层、丝印层等）。
    *   **钻孔文件生成**：同时生成钻孔文件（Drill File），用于定位板上的所有钻孔位置和尺寸。
    *   **PCB打样**：将Gerber和钻孔文件打包发送给PCB制造商进行打样生产。

4.  **元器件焊接与测试**
    *   **元器件采购**：根据原理图生成的BOM（物料清单）采购所有电子元器件。
    *   **焊接组装**：收到PCB裸板后，按照丝印层的标识，将元器件逐一焊接至正确位置。
    *   **初步测试**：焊接完成后，首先使用万用表检查电源和地之间是否存在短路，然后上电测试各关键点的电压是否正常，确保硬件电路工作正常。

### **3. 系统软件设计与实现**

#### **3.1 开发环境**

- **IDE**: Visual Studio Code + PlatformIO 插件
- **框架/SDK**: Arduino Framework for ESP32 / ESP-IDF
- **主要库**: `OneWire` & `DallasTemperature` (DS18B20), `U8g2` (OLED), `PubSubClient` (MQTT), `SD` (TF卡)

#### **3.2 主程序流程设计**

软件流程分为`setup()`初始化阶段和`loop()`主循环阶段。

```mermaid
graph TD
    subgraph setup()
        A[系统上电] --> A1[配置GPIO模式]
        A1 --> A2[初始化串口通信]
        A2 --> A3[初始化I2C并启动OLED]
        A3 --> A4[初始化SPI并挂载TF卡]
        A4 --> A5[连接Wi-Fi]
        A5 --> A6[连接MQTT服务器]
    end

    subgraph loop()
        B[循环开始] --> C{读取所有传感器数据}
        C --> D[在OLED上刷新显示]
        D --> E{判断是否发生火情}
        E -- 否 --> B
        E -- 是 --> F[执行本地报警(声光+继电器)]
        F --> G{MQTT是否连接?}
        G -- 是 --> H[发布报警信息至云端]
        G -- 否 --> I[尝试重连MQTT]
        H --> J[将报警事件写入TF卡]
        J --> B
        I --> J
    end
    
    A6 --> B
```

#### **3.3 核心功能模块实现**

1.  **数据采集模块**：
    -   **温度**：通过`DallasTemperature`库的`requestTemperatures()`和`getTempCByIndex()`函数获取DS18B20的摄氏度读数。
    -   **烟雾**：通过`analogRead()`函数读取MQ-2传感器AO引脚的电压值，该值与烟雾浓度正相关。
    -   **火焰**：通过`digitalRead()`读取DO引脚的数字信号判断有无火焰，或通过`analogRead()`读取AO引脚的模拟值判断火焰强度。

2.  **火情判断与报警模块**：
    -   设置独立的阈值，如 `TEMP_THRESHOLD = 60.0` (摄氏度)，`SMOKE_THRESHOLD = 2000` (ADC读数)，`FLAME_DETECTED = 0` (DO引脚低电平)。
    -   在主循环中，使用 `if` 语句判断 `(temp > TEMP_THRESHOLD) || (smoke > SMOKE_THRESHOLD) || (flame == FLAME_DETECTED)`。
    -   一旦条件满足，立即调用报警函数，通过`digitalWrite()`控制蜂鸣器、LED和继电器模块的GPIO引脚。

3.  **MQTT通信模块**：
    -   使用`PubSubClient`库，配置MQTT服务器地址、端口、客户端ID、用户名和密码。
    -   设备上线后，发布上线消息到特定主题，并订阅控制指令主题。
    -   当检测到报警时，将包含设备ID、分区信息（如"Floor5-Room502"）、报警类型（温度/烟雾/火焰）、实时数据等内容的JSON字符串发布到数据上报主题，例如：`{"deviceId":"ESP32_01","location":"F5-R502","type":"smoke","value":2500}`。
    -   维持心跳机制，通过`client.loop()`保持连接，并实现断线重连。

4.  **数据存储模块**：
    -   使用`SD`库初始化TF卡。
    -   当报警事件发生时，获取当前时间（可从NTP服务器同步），并格式化为字符串。
    -   将时间戳、报警类型和数据值拼接成一条日志记录，以追加模式（`FILE_APPEND`）写入到指定的日志文件（如`/fire_log.txt`）中。

### **4. 云平台与客户端设计**

1.  **云平台选择**：选用**阿里云物联网平台**或**腾讯云物联网开发平台**。这些平台提供成熟的设备管理、规则引擎、数据存储和API服务。
2.  **云端规则引擎配置**：
    -   创建一个规则，数据源为设备上报数据的主题。
    -   编写SQL（如`SELECT * FROM "your/topic" WHERE type != 'heartbeat'`）筛选报警数据。
    -   配置转发动作：当规则被触发时，将数据转发到**云函数**或**消息队列**。
    -   在云函数中调用短信服务或微信公众号模板消息接口，向绑定的手机号或微信用户发送报警通知。
3.  **移动端APP/小程序设计**：
    -   **用户认证与设备绑定**：用户通过手机号注册登录，扫描设备二维码或输入设备ID完成绑定。
    -   **实时数据面板**：通过轮询调用云平台提供的API，获取设备最新上报的数据，并以仪表盘或曲线图的形式展示。
    -   **报警通知**：集成厂商推送SDK（如APNS, FCM）或微信订阅消息，接收云端推送的报警信息，并以系统通知栏消息的形式提醒用户。
    -   **历史记录查询**：调用API查询云平台存储的历史报警数据，并以列表形式展示。
    -   **远程消音/控制**（可选）：通过APP下发指令到云平台，云平台再通过MQTT将指令转发给设备，实现远程关闭蜂鸣器或控制继电器。

### **6. 总结与展望**

#### **6.1 总结**

本项目成功设计并实现了一套功能完善的智能火灾报警系统。该系统以高性价比的ESP32-S3为核心，集成了多种传感器，实现了从数据采集、本地处理、智能报警到云端通信和远程监控的全链路功能。相较于传统报警器，本系统在智能化、信息化和响应速度方面均有显著提升，为保障小区消防安全提供了一套有效的技术方案。

#### **6.2 展望**

尽管系统已基本实现设计功能，但仍有进一步优化的空间：
1.  **低功耗设计**：引入深度睡眠（Deep Sleep）模式，并结合外部中断唤醒，在由电池供电的场景下延长续航时间。
2.  **算法优化**：引入更复杂的传感器数据融合算法（如加权平均、卡尔曼滤波），甚至边缘侧的机器学习模型，以进一步提高火情判断的准确性，减少环境干扰导致的误报。
3.  **设备组网**：利用ESP-MESH技术，使多个报警器节点自发组建成一个局域网。当一个节点报警时，可以快速通知整个网络内的其他节点，实现区域联动报警。
4.  **视频监控集成**：增加ESP32-CAM等摄像头模块，在报警时抓拍现场图片或视频流并上传，为判断火情提供更直观的依据。
