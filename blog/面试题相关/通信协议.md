# 一、基本概念

## 1. 全双工 (Full-duplex)

通信双方可以在**同一时间**进行双向数据传输。
- **示例**：打电话时，双方可以同时说话。
- **协议**：`UART` 和 `SPI` 是全双工的，因为它们有独立的发送（`TX`/`MOSI`）和接收（`RX`/`MISO`）数据线。

## 2. 半双工 (Half-duplex)

通信双方都可以收发数据，但在**同一时间只能单向**传输。
- **示例**：对讲机通话。
- **协议**：`I2C` 是半双工的，因为它使用单根数据线（`SDA`）进行双向通信。

## 3. 同步通信 (Synchronous)

通信由一根**时钟线**来协调，发送方发出数据后，会等待接收方的响应。可以看作是一种**阻塞模式**。
- **协议**：`SPI` 和 `I2C` 是同步通信，因为它们都有时钟线（`SCLK`/`SCL`）。

## 4. 异步通信 (Asynchronous)

通信**没有时钟线**，双方需预先约定好通信速率（波特率）。发送方发出数据后，不等待接收方响应。可以看作是一种**非阻塞模式**。
- **协议**：`UART` 是异步通信，它通过数据帧中的起始位和停止位来同步。

# 二、SPI vs. I2C vs. UART (单设备连接)

即使只连接一个从设备（单主单从），这三种协议在核心特性上仍有显著差异。

## 1. 核心特性对比

| 特性 | SPI (Serial Peripheral Interface) | I2C (Inter-Integrated Circuit) | UART (Universal Asynchronous Receiver/Transmitter) |
| :--- | :--- | :--- | :--- |
| **连接线数** | **4 根**：`SCLK`, `MOSI`, `MISO`, `SS/CS` | **2 根**：`SCL`, `SDA` | **2 根**：`TX`, `RX` |
| **通信速度** | **最快** (可达数十 Mbps) | **中等** (标准模式 ≤400kbps) | **较慢** (通常 < 1 Mbps) |
| **同步/异步** | 同步 (有 `SCLK` 时钟线) | 同步 (有 `SCL` 时钟线) | 异步 (无独立时钟线) |
| **双工性** | **全双工** (独立的 `MOSI`/`MISO` 线) | **半双工** (共用 `SDA` 数据线) | **全双工** (独立的 `TX`/`RX` 线) |
| **数据格式** | 连续数据流 | 消息包 (含地址、ACK) | 数据帧 (含起始/停止位) |
| **协议开销** | **最低** (无地址位等开销) | **中等** (每次通信需发送地址和 ACK) | **较高** (每字节数据都有额外位) |
| **物理层** | 推挽驱动 (驱动强，速度快) | 开漏驱动 (需上拉电阻，速度受限) | 推挽驱动 (驱动强) |

## 2. 关键区别解析

- **速度和线路 (`SPI` vs. 其他)**
    `SPI` 使用 4 根线实现全双工同步通信，且没有协议开销（如地址、ACK），使其在速度上遥遥领先。多出来的两根数据线 (`MOSI`/`MISO`) 是实现高速和全双工的关键。

- **协议开销和双向性 (`I2C` vs. 其他)**
    `I2C` 最大的特点是仅用两根线 (`SCL`, `SDA`)。为了在单根数据线 `SDA` 上实现主从切换，它必须采用半双工。同时，即使只有一个从设备，协议仍要求发送从设备地址。`SDA` 线的开漏驱动物理特性也限制了其最高速度。

- **时钟管理 (`UART` vs. `SPI`/`I2C`)**
    `UART` 是异步的，没有时钟线，因此连线最少（仅 `TX`/`RX`）。收发双方必须预先约定好波特率，并依靠数据帧中的起始/停止位进行同步。这要求双方时钟精度要足够接近。

## 3. 如何选择？

在单设备连接场景下：
- **追求最高速度**：选择 **SPI**。
- **追求最少引脚**：选择 **I2C**。
- **用于PC通信或调试**：选择 **UART**。

## 4. AT24C02使用I2C通信流程：

AT24C02开发流程：

    1. 封装I2C GPIO引脚初始化和高低电平操作函数
    2. 封装I2C起始信号、停止信号、应答信号、非应答信号函数
    3. 封装I2C发送一个字节和接收一个字节函数
    4. 封装AT24C02写入一个字节和读取一个字节函数
    5. 封装AT24C02写入多个字节和读取多个（函数参数为指定的地址、读写数据的长度和数据）

I2C使用的时候，写操作流程为：

    1. 发送起始信号
    2. 发送器件地址+写位
    3. 等待应答
    4. 发送数据地址高8位
    5. 等待应答
    6. 发送数据地址低8位
    7. 等待应答
    8. 发送数据
    9. 等待应答
    10. 发送停止信号

I2C使用的时候，读操作流程为：

    1. 发送起始信号
    2. 发送器件地址+写位
    3. 等待应答
    4. 发送数据地址高8位
    5. 等待应答
    6. 发送数据地址低8位
    7. 等待应答
    8. 发送起始信号
    9. 发送器件地址+读位
    10. 主机释放SDA线
    11. 等待应答
    12. 接收数据
    13. 主机向从机发送非应答信号
    14. 发送停止信号

针对AT24C02：

- 写一个字节：发送器件地址+写位，发送数据地址高8位，发送数据地址低8位，发送数据
- 读一个字节：发送器件地址+写位，发送数据地址高8位，发送数据地址低8位，发送器件地址+读位，接收数据

读的时候指定地址，是因为需要先告诉AT24C02要读取哪个地址的数据，写的时候指定地址，是因为需要告诉AT24C02要把数据写入到哪个地址。

为什么不能直接带地址读取呢？因为I2C协议规定，一次传输只能是单向的，不能在同一个传输方向里混合发送和接收。

    ┌────────────────────────────────────────────────────────────────────┐
    │                    I2C 协议的铁律                                   │
    ├────────────────────────────────────────────────────────────────────┤
    │  发送地址字节后，R/W 位决定了后续所有字节的传输方向：               │
    │                                                                    │
    │  • R/W = 0（写）：后续所有字节都是 主机 → 从机                     │
    │  • R/W = 1（读）：后续所有字节都是 从机 → 主机                     │
    │                                                                    │

    └────────────────────────────────────────────────────────────────────┘

## 6. SPI和I²C他们两个之间寻址的差异讲一下。

答：**寻址方式**的差异是SPI和I²C的核心区别之一

SPI：**硬件地址**，通过**片选信号**（CS） 寻址，每个从机**独立连接CS线，主机拉低某一CS线选中对应从机**，而其他从设备的CS线保持高电平（无效）。

I²C：**软件寻址**。总线上**设备共享 SDA（数据）和 SCL（时钟）**，主机先发送 7 位 / 10 位从机地址，仅地址匹配的从机响应。

所有**从设备**都会**监听这个地址**，只有地址匹配的从设备才会响应后续的数据传输。

## 7.I²C是一主多从，那它可以带多少个从机？

答：**I²C总线**所能挂载的**从机数量**理论上和实际上受**两个因素**限制：

**a.地址空间限制**：

标准模式I²C使用**7位地址**,其中**有16个地址被保留**用于特殊用途，所以可用的地址有 128 - 16 = 112个。

因此，从理论上讲，在**一条总线**上最多**可以挂载** **112个具有不同7位地址的从机设备**。

如果**使用10位地址**模式，则理论上可以挂载 **1024个设备**，但这种模式较少见。

**b.总线电容限制（物理限制）**：

I²C总线规范规定了**总线的最大容限**（标准模式为400pF）,**每增加一个从机**，就会给总线增加一定的寄生电容。

当**总线上设备过多，总电容超过限制时，信号上升/下降时间会变长，导致波形畸变**，通信会变得不可靠甚至失败。

总之：在**7位地址模式**下，理论**最大值为112个**，但实际设计中，由于总线电容的限制，通常**只会挂载几个到十几个从机**，如果需要更多，可以使用I²C多路复用器（如TCA9548A）来扩展多条总线。
