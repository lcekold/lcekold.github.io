# 项目描述

* **项目描述**：本项目基于泰山派开发板构建学习辅助系统，上位机运行用户界面并集成YOLOv11n模型实现实时学习状态检测；下位机以ESP32为主控单元，负责环境数据采集与设备控制。系统可智能监督用户学习行为、提供便捷的学习支持功能，有效提升专注度与学习氛围。

* 负责内容：

1. 基于QT框架开发上位机界面，使用QSS进行整体视觉美化；集成DeepSeek API实现智能问答模块，通过QNetworkAccessManager发送HTTP请求并解析JSON响应，结合QTextToSpeech实现语音播报功能。

2. 采用SQLite数据库存储备忘录信息，通过单例模式管理数据库连接，利用QsqlQuery事务机制实现数据的可靠增删改查。

3. 使用QPainter自定义绘制温湿度仪表盘，借助QChart实现动态曲线可视化；通过QSerialPort类与下位机进行串口通信，实现数据的稳定收发。

4. 下位机基于ESP32平台，通过MQTT协议将传感器数据实时上传至服务器，支持手机客户端订阅并远程查看环境数据及设备状态；同时通过串口与泰山派通信，支持通过手机App或终端助手控制灯光与风扇。应用FreeRTOS队列与事件机制优化任务调度，提升系统实时性和多任务处理能力。

5. 独立完成ESP32主控板的PCB设计、手工焊接与系统级测试，保障硬件模块稳定可靠运行。

## **问题 3**: 数据库与单例模式

* **面试官**： “为什么在SQLite数据库连接上使用单例模式？能说说它的好处和你具体是怎么实现的吗？”

* **考察点**： 对设计模式的理解和实际应用能力。

* **回答思路**： 解释单例模式的目的，结合数据库连接的特殊性说明好处，并简要提及实现方式（如静态指针、线程安全）。

* **参考回答**：

    “使用单例模式是为了保证整个应用程序中只有一个数据库连接实例。
    这样做有两个主要好处：一是避免资源冲突，如果多个连接同时操作数据库，很容易导致数据错乱或锁表；二是节省系统资源，频繁地创建和关闭数据库连接是非常耗时的。
    在我的实现中，我创建了一个DatabaseManager类，将它的构造函数私有化，并提供了一个静态的getInstance()方法来获取唯一的实例。在这个方法内部，我使用了一个静态指针来确保实例只被初始化一次。同时，为了在QT多线程环境下安全，我确保了所有数据库操作都在主线程中完成，或者使用了线程锁来保证安全。”

## **问题 4**: 硬件与实时系统

**面试官**： “你提到了FreeRTOS的队列和事件机制。能举一个具体的例子说明你是如何用它们来提升实时性和多任务响应能力的吗？”

*   **考察点**： 对嵌入式实时操作系统的理解，解决实际问题的能力。

*   **回答思路**： 选择一个典型场景（如传感器数据读取+网络发送），说明没有RTOS时的问题，再阐述如何用队列和事件优雅地解决。

*   **参考回答**：

    “当然可以。比如，我有两个主要任务：任务A‘读取温湿度传感器’，任务B‘通过Wi-Fi发送数据’。
    如果没有队列，任务A读取到数据后，可能需要等待任务B完成上一次发送才能写入，这会造成数据丢失或延迟。
    我的做法是：任务A在读取到传感器数据后，立刻通过xQueueSend()将数据打包发送到一个消息队列中，然后它立刻回去进行下一次读取，效率很高。任务B则阻塞在xQueueReceive()上，一旦队列中有数据，它就被唤醒，取出数据并进行网络发送。
    这样，通过队列这个缓冲区和解耦器，两个任务可以独立以自己的频率运行，生产者（任务A）不用等待消费者（任务B），极大地提升了系统的实时性和可靠性。事件组则用于同步，比如用于等待‘Wi-Fi连接成功’这个事件发生后，任务B才开始工作。”

    * **参考回答**：

        我将整个系统分解为几个任务：

        * 一个高优先级任务：负责处理串口接收中断抛出的数据，并将其快速放入队列中。它的职责是尽快离开中断上下文，不让中断被长时间阻塞。

        * 一个中优先级任务：作为主逻辑任务，它阻塞在队列上，等待处理来自串口的数据包。解析后，它会将需要发送的数据通过另一个队列发送给...

        * 一个低优先级任务：MQTT发布任务。它负责从自己的队列中取出数据，执行网络操作。网络操作延迟高且不稳定，所以它的优先级最低，不会阻塞更关键的系统任务。

# UART+DMA 不定长数据收发+环形缓冲区的实现

通过UART+DMA实现不定长数据收发，结合环形缓冲区来处理数据的接收和发送，可以有效地提高数据传输效率和系统响应速度。以下是一个简单的实现思路：

##### 1. 硬件配置

确保UART和DMA的硬件配置正确。通常需要设置以下参数：
- UART波特率
- 数据位、停止位、校验位
- DMA通道配置
- DMA传输方向（从外设到内存或从内存到外设）
##### 2. 环形缓冲区设计
环形缓冲区是一个固定大小的缓冲区，使用两个指针（头指针和尾指针）来管理数据的读写。以下是环形缓冲区的基本结构：

```c
#define BUFFER_SIZE 256 // 缓冲区大小
typedef struct {
    uint8_t buffer[BUFFER_SIZE]; // 数据缓冲区
    volatile uint32_t head;       // 头指针
    volatile uint32_t tail;       // 尾指针
} RingBuffer;
RingBuffer ringBuffer;
```
##### 3. 初始化环形缓冲区
```c
void RingBuffer_Init(RingBuffer *rb) {
    rb->head = 0;
    rb->tail = 0;
}
```
##### 4. DMA接收数据
使用DMA接收数据时，将接收到的数据存储到环形缓冲区中。可以在DMA传输完成中断中处理数据。

```c
void DMA_UART_Receive_IRQHandler(void) {
    // 假设DMA接收完成后会触发中断
    uint32_t receivedLength = DMA_GetReceivedDataLength(); // 获取接收到的数据长度
    for (uint32_t i = 0; i < receivedLength; i++) {
        ringBuffer.buffer[ringBuffer.head] = DMA_ReadData(); // 从DMA读取数据
        ringBuffer.head = (ringBuffer.head + 1) % BUFFER_SIZE; // 更新头指针
        if (ringBuffer.head == ringBuffer.tail) {
            // 缓冲区满，处理溢出（例如丢弃旧数据或覆盖）
            ringBuffer.tail = (ringBuffer.tail + 1) % BUFFER_SIZE; // 覆盖旧数据
        }
    }
}
```
##### 5. DMA发送数据
发送数据时，可以从环形缓冲区中读取数据，并通过DMA发送出去。

```c
void DMA_UART_Send(RingBuffer *rb) {
    while (rb->tail != rb->head) { // 当缓冲区不为空时
        uint8_t data = rb->buffer[rb->tail]; // 读取数据
        DMA_WriteData(data); // 通过DMA发送数据
        rb->tail = (rb->tail + 1) % BUFFER_SIZE; // 更新尾指针
    }
}
```
##### 6. 使用示例
```c
int main(void) {
    RingBuffer_Init(&ringBuffer); // 初始化环形缓冲区

    // 配置UART和DMA
    UART_Config();
    DMA_Config();

    // 启动DMA接收
    DMA_UART_StartReceive();

    while (1) {
        // 主循环中可以处理其他任务
        if (DataAvailable(&ringBuffer)) { // 检查是否有数据可用
            DMA_UART_Send(&ringBuffer); // 发送数据
        }
    }
}
```
##### 7. 注意事项
- 确保环形缓冲区的大小足够大，以容纳预期的最大数据量。
- 在多线程或中断环境中访问环形缓冲区时，需要使用适当的同步机制（如禁用中断）来防止数据竞争。
- 处理缓冲区满的情况时，可以选择丢弃旧数据或覆盖旧数据，具体取决于应用需求。
#####

##### 8. 总结
通过使用UART和DMA结合环形缓冲区，可以实现高效的不定长数据收发。这种方法能够减少CPU的负担，提高数据传输的实时性和可靠性。环形缓冲区的设计使得数据的读写操作更加灵活，适用于多种嵌入式应用场景。
   
### 简化过程

要实现UART+DMA不定长数据收发可以通过，UART触发空闲中断，然后通过DMA传输过半中断/DMA传输完成中断 来处理数据，将数据写入环形缓冲区。

#### 双缓冲机制：
将DMA缓冲区设定为二维数组buf[2][N],在DMA开始工作是会先将数据存放到buf[0]中，当触发DMA半传输中断时，即表示buf[0]已存满，系统会转到buf[1]中缓存，这时你就可以及时处理buf[0]中的数据了，当触发DMA全传输中断时，即表示buf[1]已存满，系统会转到buf[0]中缓存，这时你就可以及时处理buf[1]中的数据了。即实现无缝数据流采集和并行处理。
