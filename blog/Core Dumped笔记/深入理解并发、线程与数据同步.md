并发：在单核系统中，CPU的核心是共享的，每个线程轮流执行，切换的速度非常快，看起来就像同时运行一样。

并行：在多核系统中，CPU的核心是独立的，每个线程可以在不同的核心上同时运行。

而在并发的线程中，线程之间进行数据共享时，可能会出现问题。

以一个例子为例，我们现在需要将一个字符串发送给客户端，字符串的内容是由一个线程定期更新的，而另一个线程则负责处理客户端的请求并将当前字符串发送给客户端。

许多人会定义一个全局变量来存储当前字符串，创建一个定期更新它的函数，并启动一个执行该函数的线程，写入线程只需根据需要修改这个变量，而处理线程在需要响应客户端时读取该变量。

但是针对字符串的操作并非原子操作，字符串的更新可能会被中断，导致处理线程读取到一个不完整的字符串，从而出现错误。

而这就是竞态条件的典型例子，竞态条件是指两个或多个线程在访问共享数据时，由于线程调度的不可预测性，导致程序的行为不确定。竞争条件通常是抢占式操作系统带来的副作用，抢占式操作系统是指操作系统可以在任何时候暂停一个线程的执行，并将CPU分配给另一个线程，这种调度方式虽然提高了系统的响应性，但也带来了数据一致性的问题。

这里在设计CPU调度额时候，还要提到时间片的概念，时间片是指操作系统为每个线程分配的CPU执行时间的长度，时间片的长度通常是固定的，如果一个线程或进程在其时间片耗尽之前未能完成当前任务，硬件定时器会触发一个中断，抢占该进程，这意味着操作系统会暂停它并将CPU重新分配给其它任务。

然而这不代表在较短的时间内完成操作就是安全的，除了时间问题之外，CPU还可能被许多与调度器无关的其他事件中断，其他进程设置的定时器，用户在用户界面中按下按钮，传入的网络数据包，这些都可能成为中断的来源，这类事件会触发中断，而无论中断源自何处，都可能抢占当前正在运行的线程。

如果我们引入一个控制变量，一个标志用于指示共享数据，当前是否正在被修改，例如1表示正在写入，0表示未在写入，通过这种设置，想要从共享字符串读取的线程可以先检查该标志，以查看写入线程是否正在修改它，现在尽管这听起来可能是个好主意，但我们需要保持谨慎，因为一旦这个控制变量在多个线程之间共享，它就变成了共享数据，因此也容易受到竞争条件的影响。在某些架构上设置或检查变量值的操作，并不总是原子的，某个变量的写入可能是原子的，但读取值几乎从来都不是原子操作，这通常涉及将变量的值从内存加载到寄存器中，将该寄存器的值与某个常量或预期值进行比较，然后根据比较结果执行相应操作。

# 解决双线程互斥的常用方法——Peterson算法

```c
Pi进程：                                                                   
flag[i] = True;
turn = j;
while(flag[j] && turn == j);
critical section;
flag[i] = False;
remainder section;

Pj进程：                                                                   
flag[j] = True;
turn = i;
while(flag[i] && turn == i);
critical section;
flag[j] = False;
remainder section;
```

怎么理解变量turn呢？可以将turn变量理解成轮到谁进入临界区了。举个例子：turn = i，表示轮到Pi进入临界区。那么上面这个代码就可以理解为：首先，Pi想进入临界区（flag[i] = True），然后，还是和前面的代码一样，Pi会先把进入临界区的机会让给Pj（turn = j），同样地，当Pj想进入临界区时，也会将进入临界区的权利先让给Pi。紧接着，变量turn的作用就显现出来了，当Pj把进入临界区的机会又让给Pi的时候（注意：这是发生在Pi将进入临界区的优先权让给Pj之后），Pi这次就会直接进入临界区。就不会再次出现一直互相谦让，最终导致均无法进入临界区的情况了。

但是依然存在一个问题，就是编译器实际上会对代码进行优化，可能会将flag[i] = True;和turn = j;这两行代码进行重排，导致Pi进程在执行完flag[i] = True;之后，turn = j;还没有执行完，就被Pj进程抢占了CPU，Pj进程也执行了flag[j] = True;和turn = i;，这时就会出现两个进程都在等待对方释放临界区的情况，从而导致死锁。

并且现在的很多CPU为了提高性能，都会对指令进行乱序执行，这就会导致Pi进程在执行完flag[i] = True;之后，turn = j;还没有执行完，就被Pj进程抢占了CPU，Pj进程也执行了flag[j] = True;和turn = i;，这时就会出现两个进程都在等待对方释放临界区的情况，从而导致死锁。

所以这个事情告诉我们，软件层面并不能完全解决多线程之间的互斥问题，因此需要硬件层面也支持原子操作。确保编译器优化，CPU重排序或者缓存机制都不会影响其执行过程。
