# 一个简单的示例：替代二值信号量

假设一个中断服务程序需要通知一个任务处理数据。

## 发送方（在 ISR 中）：

```c
void vAN_ISR(void) {
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    // ... 中断处理逻辑

    // 直接给目标任务（xHandlerTask）发送通知，相当于给出信号量
    vTaskNotifyGiveFromISR(xHandlerTask, &xHigherPriorityTaskWoken);

    // 如果需要，执行上下文切换
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}
```

## 接收方（任务中）：

```c
void vHandlerTask(void *pvParameters) {
    for (;;) {
        // 无限等待通知的到来（第二个参数为 pdTRUE，模拟二值信号量，退出时清零）
        ulTaskNotifyTake(pdTRUE, portMAX_DELAY);

        // 收到通知，开始处理业务
        process_data();
    }
}
```

# 使用任务通知来替代事件组

## 示例：按键按下和数据到达双事件触发

假设我们有一个数据处理任务（vDataTask），它需要同时等待两个事件：

1. 事件 A（位 0）： 一个按键被按下（由 GPIO 中断服务程序设置）。

2. 事件 B（位 1）： 一串数据通过 UART 接收完成（由 UART 中断服务程序设置）。

只有当这两个事件都发生后，任务才执行相应的操作。

### 1. 定义事件标志位

```c
// 在头文件中定义事件标志位，每个位代表一个独立事件
#define TASK_EVENT_BUTTON_PRESSED    (1UL << 0) // 第 0 位：按键按下
#define TASK_EVENT_UART_DATA_READY   (1UL << 1) // 第 1 位：UART数据就绪
// #define TASK_EVENT_XXX            (1UL << 2) // 可以继续定义更多事件
```

### 2. 发送方（在中断中设置事件位）

GPIO 中断服务程序（设置按键按下位）：

```c
// 假设已经获取了接收任务 xDataTaskHandle 的句柄
extern TaskHandle_t xDataTaskHandle;

void vButton_ISR(void) {
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    // 清除中断标志等操作...
    
    // 关键：使用 eSetBits 动作，将 BUTTON 位“或”到目标任务的通知值中
    xTaskNotifyFromISR(xDataTaskHandle, 
                       TASK_EVENT_BUTTON_PRESSED, 
                       eSetBits, 
                       &xHigherPriorityTaskWoken);

    // 执行上下文切换
    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}
```

UART 中断服务程序（设置数据就绪位）：

```c
extern TaskHandle_t xDataTaskHandle;

void vUART_ISR(void) {
    BaseType_t xHigherPriorityTaskWoken = pdFALSE;

    // 接收数据，判断数据包完整...
    
    // 关键：使用 eSetBits 动作，将 UART 位“或”到目标任务的通知值中
    xTaskNotifyFromISR(xDataTaskHandle, 
                       TASK_EVENT_UART_DATA_READY, 
                       eSetBits, 
                       &xHigherPriorityTaskWoken);

    portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
}
```

**注意**： 两个不同的中断源（发送者）都在操作同一个任务（xDataTaskHandle）的同一个通知值。

### 3. 接收方（任务中等待事件位）

```c
void vDataTask(void *pvParameters) {
    uint32_t ulNotifiedValue;
    const TickType_t xMaxBlockTime = pdMS_TO_TICKS(1000);
    
    for (;;) {
        // 等待我们关心的事件位（任意一个或全部）被设置
        // ulBitsToClearOnEntry: 等待前不清除任何位，保证能累积事件
        // ulBitsToClearOnExit: 退出时，清除我们关心的所有位，为下一次等待做准备
        // pulNotificationValue: 用于取出当前的通知值，以便判断哪些位被设置了
        // xMaxBlockTime: 最大阻塞时间
        
        xReturn = xTaskNotifyWait(0, // 进入时不清除任何位
                                 (TASK_EVENT_BUTTON_PRESSED | TASK_EVENT_UART_DATA_READY), // 退出时清除所有关心的位
                                 &ulNotifiedValue, // 获取通知值的状态
                                 xMaxBlockTime);

        if (xReturn == pdPASS) {
            // 成功收到通知，检查是哪些事件发生了
            if ((ulNotifiedValue & TASK_EVENT_BUTTON_PRESSED) != 0) {
                // 按键事件已发生
                // 可以在这里处理，或者只是记录标志，等待所有事件齐全
            }

            if ((ulNotifiedValue & TASK_EVENT_UART_DATA_READY) != 0) {
                // 数据就绪事件已发生
            }

            // 检查是否两个事件都发生了
            if ((ulNotifiedValue & (TASK_EVENT_BUTTON_PRESSED | TASK_EVENT_UART_DATA_READY)) 
                == (TASK_EVENT_BUTTON_PRESSED | TASK_EVENT_UART_DATA_READY)) {
                
                // 两个必要事件都已发生！
                process_events(); // 执行核心操作
            }
            // 如果只发生了其中一个，则继续循环等待（因为位已被清除，需要另一个中断来设置）
        } else {
            // 超时处理
        }
    }
}
```

### 另一种等待逻辑：等待所有位同时置位

如果你希望任务一次性等待所有所需事件同时发生，而不是在循环中自己检查，可以稍作修改：

```c
void vDataTask(void *pvParameters) {
    uint32_t ulNotifiedValue;
    const uint32_t ulBitsToWaitFor = (TASK_EVENT_BUTTON_PRESSED | TASK_EVENT_UART_DATA_READY);

    for (;;) {
        // 先清除我们关心的所有位，确保从干净的状态开始等待
        xTaskNotifyWait(ulBitsToWaitFor, // 进入时，先清除所有关心的位
                       ulBitsToWaitFor, // 退出时，再次清除所有关心的位
                       &ulNotifiedValue,
                       portMAX_DELAY); // 无限等待

        // 能执行到这里，说明 ulBitsToWaitFor 中的所有位都被设置过了
        // (因为xTaskNotifyWait会在位被设置后才会退出，并且退出时会清除位)
        process_events(); // 执行核心操作
    }
}
```

这种方式的逻辑是：xTaskNotifyWait 会在任何位被设置时唤醒任务。但我们在循环中并不关心中间状态，我们只是不断地清除这些位并重新等待，直到某一次xTaskNotifyWait返回时，意味着在我们清除之后，所有需要的位又一次被设置齐了。这更接近于事件组的“与”等待（xEventGroupWaitBits 且设置 xWaitForAllBits 为 pdTRUE）。

### 总结

通过使用 xTaskNotify(... eSetBits ...) 和 xTaskNotifyWait()，任务通知可以有效地模拟事件组的核心功能。

* **优势**： 速度和内存效率远超传统事件组。

* **劣势**： 仅适用于“多对一”的场景（多个发送者，一个接收者任务）。无法让多个任务等待同一组事件。

在选择时，务必根据你的具体应用架构来决定是使用轻量级的任务通知还是功能更全面的传统事件组。
