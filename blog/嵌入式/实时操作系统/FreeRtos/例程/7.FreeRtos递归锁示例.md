# 举例说明

## 场景：

我们有一个共享的全局变量 shared_counter 需要保护。有两个函数：一个高级函数 high_level_function() 和一个低级函数 low_level_function()。高级函数会调用低级函数，并且它们都需要操作 shared_counter。

### 1. 创建递归互斥锁

```c
#include <FreeRTOS.h>
#include <semphr.h>

// 声明一个递归互斥锁句柄
SemaphoreHandle_t xRecursiveMutex;

void main_app_code( void )
{
    // 创建递归互斥锁
    xRecursiveMutex = xSemaphoreCreateRecursiveMutex(); // 注意这个特定的创建函数

    if( xRecursiveMutex != NULL )
    {
        // 创建任务等后续操作
        // ...
    }
}
```

### 2. 任务函数示例

```c
// 低级函数，需要获取锁
void low_level_function( void )
{
    // 获取递归锁。如果当前任务已经持有它，则成功返回，计数器+1
    if( xSemaphoreTakeRecursive( xRecursiveMutex, portMAX_DELAY ) == pdTRUE )
    {
        // 临界区开始 - 安全地操作共享资源
        shared_counter++;
        // 也许还有其他操作...
        // 临界区结束

        // 释放递归锁。计数器-1，如果计数器减到0，则真正释放锁。
        xSemaphoreGiveRecursive( xRecursiveMutex );
    }
}

// 高级函数，也需要获取锁，并且会调用低级函数
void high_level_function( void )
{
    // 获取递归锁（第一次获取，计数器从0->1）
    if( xSemaphoreTakeRecursive( xRecursiveMutex, portMAX_DELAY ) == pdTRUE )
    {
        // 临界区开始
        shared_counter *= 2; // 先做一些高级操作

        // 现在调用低级函数
        low_level_function(); // 这个函数内部也会尝试获取同一个递归锁

        // 还可以继续安全地使用 shared_counter
        // 临界区结束

        // 释放递归锁（这是对应第一次获取的释放，计数器从1->0，锁被真正释放）
        xSemaphoreGiveRecursive( xRecursiveMutex );
    }
}

// 任务函数
void myTask( void * pvParameters )
{
    for( ;; )
    {
        // 任务执行一些工作...
        high_level_function(); // 调用高级函数
        vTaskDelay( pdMS_TO_TICKS( 1000 ) );
    }
}
```

### 执行流程分析：

1. 任务 myTask 运行，调用 high_level_function()。

2. high_level_function() 调用 xSemaphoreTakeRecursive，成功获取 xRecursiveMutex。锁计数器变为 1。锁的所有者是 myTask。

3. high_level_function() 开始执行其临界区代码（例如 shared_counter *= 2;）。

4. high_level_function() 调用 low_level_function()。

5. low_level_function() 调用 xSemaphoreTakeRecursive 尝试获取同一个 xRecursiveMutex。

    * 关键点：FreeRTOS 内核检查到当前调用任务 (myTask) 已经是该锁的所有者。

    * 结果：获取成功，函数立即返回 pdTRUE。锁计数器增加为 2。

6. low_level_function() 执行其临界区代码（例如 shared_counter++;）。

7. low_level_function() 调用 xSemaphoreGiveRecursive 来释放锁。

    * 内核将锁计数器从 2 减为 1。

    * 因为计数器不为 0，锁并没有真正释放，仍然被 myTask 持有。

    * 其他任务仍然无法获取这个锁。

8. low_level_function() 返回，继续执行 high_level_function() 中剩下的代码。

9. high_level_function() 执行完毕，调用 xSemaphoreGiveRecursive。

    * 内核将锁计数器从 1 减为 0。

    * 计数器为 0，锁被真正释放，现在可供其他任务获取。

10. 整个调用链完成，没有发生任何死锁。

## 重要总结

1. <b>专用 API:</b>FreeRTOS 为递归锁提供了专用的 API 函数：

    * xSemaphoreCreateRecursiveMutex()：用于创建递归互斥锁。

    * xSemaphoreTakeRecursive()：用于获取递归锁。

    * xSemaphoreGiveRecursive()：用于释放递归锁。
必须使用这些配套的函数，如果对递归锁使用普通的 xSemaphoreTake/xSemaphoreGive，会导致未定义行为（通常是断言失败或崩溃）。

2. <b>优先级继承：</b>与普通互斥锁一样，FreeRTOS 的递归互斥锁也具有优先级继承机制，可以防止优先级反转问题。

3. <b>使用场景：</b>当你设计一个可能被多重调用的函数库，或者一个复杂任务中不同层级的函数都需要访问同一个资源时，递归锁是非常有用的工具。它提供了灵活性，但应谨慎使用，因为过度使用会导致代码结构复杂，难以维护。
