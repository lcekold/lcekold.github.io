# 第5章 EtherCAT 伺服驱动器控制应用协议

> 本章解决的问题：**控制器怎么通过 EtherCAT 控制一台伺服驱动器？** 两条路线——用 **CoE** 走 CANopen 的 CiA402 行规，或用 **SoE** 走 SERCOS 行规。

## 开篇背景：IEC 61800-7 与四种行规

**图 5.1　IEC 61800-7 体系结构**（原书 p.112）

<img src="https://cdn.jsdelivr.net/gh/lcekold/lcekold.github.io/img/ethercat/ethercat-book/F067_p112.png" alt="图 5.1 IEC 61800-7 体系结构">

IEC 61800 系列是**可调速电子功率驱动系统**的通用规范。其中 **IEC 61800-7 定义了控制系统和功率驱动系统之间的通信接口标准**，内容包含**网络通信技术**和**应用行规**两半。行规按风格分 4 类，各自映射到不同网络：

| 行规类型 | 应用行规 → 映射到的网络 | 行规类型 | 应用行规 → 映射到的网络 |
| --- | --- | --- | --- |
| 类型 1 | CiA402 → CANopen、DeviceNet、EtherCAT 等 | 类型 2 | CIP Motion → ControlNet、EtherNet/IP 等 |
| 类型 3 | PROFIdrive → PROFIBUS、PROFINET | 类型 4 | SERCOS → SERCOS I+II、SERCOS III、EtherCAT |

EtherCAT 作为网络通信技术，同时支持了 CANopen 的 **CiA402** 行规和 **SERCOS** 的应用层，分别称为 **CoE** 和 **SoE**。

## 5.1 CoE（CANopen over EtherCAT）

CANopen 最初是为 CAN 总线系统制定的应用层协议，EtherCAT 在应用层支持它并做了扩充，主要功能三条：① 用**邮箱通信**访问 CANopen 对象字典，实现**网络初始化**；② 用 CANopen **应急对象**和事件驱动的 **PDO** 消息，实现**网络管理**；③ 用**对象字典映射过程数据**，周期性传输指令数据和状态数据。一句话记住分工：**配置和管理走非周期的邮箱，实时控制走周期的过程数据。**

### 5.1.1 CoE 对象字典

**图 5.2　PDO 分配示意图**（原书 p.114）

<img src="https://cdn.jsdelivr.net/gh/lcekold/lcekold.github.io/img/ethercat/ethercat-book/F068_p114.png" alt="图 5.2 PDO 分配示意图">

CoE 完全遵从 CANopen，对象字典的定义也相同，按索引号分五大区间：

| 索引号范围 | 含义 |
| --- | --- |
| 0x0000~0x0FFF | 数据类型描述 |
| 0x1000~0x1FFF | 通信对象：设备类型、标识符、PDO 映射（与 CANopen 兼容）；CANopen 专用数据对象在 EtherCAT 中保留；以及 **EtherCAT 扩展数据对象** |
| 0x2000~0x5FFF | 制造商定义对象 |
| 0x6000~0x9FFF | 行规定义数据对象 |
| 0xA000~0xFFFF | 保留 |

关键通信对象（每个一句话说清用途）：

| 索引 | 用途 |
| --- | --- |
| 0x1000 | **设备类型**，32 位：位 0~15 = 使用的设备行规（**CiA402 编号 402 = 0x0192**），位 16~31 = 行规附加信息 |
| 0x1001 | 错误寄存器，8 位：位 0 常规错误、位 1 电流、位 2 电压、位 3 温度、位 4 通信、位 5 设备行规定义、位 7 制造商定义 |
| 0x1008 / 0x1009 / 0x100A | 设备名称 / 制造商硬件版本 / 制造商软件版本 |
| 0x1018 | **设备标识符**，结构体：子索引 0 数目、1 制造商 ID、2 产品码、3 版本号、4 序列号——主站靠它认设备，是**扫到设备后读的第一批参数** |
| 0x1600~0x17FF / 0x1A00~0x1BFF | **RxPDO 映射 / TxPDO 映射**：子索引 0 = 映射的数据对象数目，子索引 1..n = 被映射的数据对象 |
| 0x1C00 | **同步管理器通信类型**：子索引 0 = SM 数目，子索引 11~32 对应 SM0~SM3 的通信类型（`0` 邮箱输出、`1` 邮箱输入为非周期；`2` 过程数据输出、`3` 过程数据输入为周期） |
| 0x1C10~0x1C2F | **过程数据通信同步管理器 PDO 分配**：子索引 0 = 分配的 PDO 数目，子索引 1..n = PDO 映射对象索引号 |
| 0x1C30~0x1C4F | **同步管理器参数**：子索引 1 = 同步类型，2 = 周期时间[ns]，3 = AL 事件和相关操作之间的偏移量[ns] |

> **注意**：0x1C00~0x1C4F 是 **EtherCAT 对 CANopen 的扩展**，专门用于设置同步管理器的类型、通信参数和 PDO 数据分配，标准 CANopen 里没有这些对象。

### 5.1.2 周期性过程数据通信

过程数据可以由多个 PDO 映射数据对象拼成；CoE 用对象 0x1C10~0x1C2F 定义相应 SM 通道的 PDO 映射对象列表。以周期性**输出**数据为例：输出数据走 **SM2** 通道，由对象 **0x1C12** 定义 PDO 分配。

```
0x1C12（SM2 的 PDO 分配）           0x1600（第 1 个 PDO 的映射内容）
  子索引 0 = 3    PDO 数目            子索引 0 = 2    映射对象数目
  子索引 1 = 0x1600                  子索引 1 = 0x7000:01  电流模拟量输出（2 字节）
  子索引 2 = 0x1601                  子索引 2 = 0x7010:01  电流模拟量输出（2 字节）
  子索引 3 = 0x1602                  0x1601 装 0x7020:01、0x7030:01；0x1602 装 0x7040:01、0x7050:01
```

可见 0x1C12 说"这个通道挂了 3 个 PDO"，每个 PDO 映射对象再说明自己装了什么：0x1600 装两个 2 字节对象就是 4 字节，三组字节数累加就是整段过程数据的长度。于是形成**三层映射链**：`数据对象（0x6040 控制字…） → PDO 映射对象（0x1600） → PDO 分配对象（0x1C12） → SM 通道 → EtherCAT 帧的逻辑地址`

> 类比填快递面单：0x1C12 说"这个箱子装 3 个包裹"，0x1600 说"第 1 个包裹是控制字、第 2 个是目标位置"，于是整箱东西在帧里的排布就确定下来了。

按设备复杂程度，PDO 映射有四种形态：① **简单设备不需要映射协议**——用固定过程数据，从从站 EEPROM 读取，不需要 SDO 协议；② **可读取的 PDO 映射**——固定映射，可用 SDO 通信读取；③ **可选择的 PDO 映射**——多组固定 PDO 通过 PDO 分配对象 0x1C1x 用 SDO 通信选择；④ **可变的 PDO 映射**——可通过 CoE 通信配置，PDO 内容可改变。

主站通过读写邮箱数据 **SM 通道**实现非周期通信（邮箱机制见 2.5.2）。邮箱数据头之后是 **2 字节 CoE 头**：位 0~8 = PDO 编号，位 9~11 保留，位 12~15 = **服务类型**：

| 值 | 服务类型 | 值 | 服务类型 |
| --- | --- | --- | --- |
| 0 / 1 | 保留 / 紧急事件信息 | 2 / 3 | SDO 请求 / SDO 响应 |
| 4 / 5 | TxPDO / RxPDO | 6 / 7 | 远程 TxPDO 发送请求 / 远程 RxPDO 发送请求 |
| 8 / 9~15 | SDO 信息 / 保留 |  |  |

**（1）SDO 的三种传输服务**：**快速传输**与标准 CANopen 相同，只用 8 字节（其中 4 字节数据区），最多传 4 字节有效数据；**常规传输**使用超过 8 字节，可传超过 4 字节，最大有效数据取决于邮箱 SM 管理的存储区容量（最大有效数据 = 邮箱容量 − 16）；**分段传输**用于数据超过邮箱容量的情况。SDO 又分**下载**（主站设置从站参数）和**上传**（主站读取从站参数），物理上对称，下面只讲下载。

**（2）SDO 下载请求**：控制字节的关键位含义如下，其后依次是 2 字节索引号、1 字节子索引号、数据。CCS 里的"请求/响应"是**站在发起方角度**定义的，读报文时别把方向搞反。

| 位 | 名称 | 含义 |
| --- | --- | --- |
| 0 | Size Indicator | 0 = 未指定传输字节数目，1 = 已指定 |
| 1 | Transfer Type | 1 = 快速传输，0 = 常规/分段传输 |
| 2~3 | Data set Size | 快速传输时的有效数据字节数 = 4 − 该值（常规/分段传输时无效） |
| 4 | Complete Access | 0 = 只操作索引号 + 子索引号检索的对象；1 = 操作完整对象（子索引应为 0 且大于 1 字节） |
| 5~7 | CoE 命令码 CCS | 0x01 下载请求、0x00 分段下载请求、0x03 下载响应、0x04 终止传输请求 |

**（3）SDO 分段下载**：常规下载时若传输数据总量大于本次允许量，必须用后续分段下载。分段控制字节：位 0 = 是否有后续分段（0 = 有后续、1 = 最后一段）；位 1~3 = SegData Size（最后 7 个字节中的有效字节数 = 7 − 该值）；位 4 = **Toggle 翻转握手位**（每次分段下载请求翻转，从 0 开始）；位 5~7 = CCS = 0x00 分段下载请求；每帧数据最多 7 字节。

> **Toggle 位的设计意图**：分段传输最怕"重传的旧段被当成新段"。翻转位让每一段都带一个 0/1 交替的标记，接收方发现翻转位没变，就知道这是**重传的旧段**——相当于给每一页装上"页码奇偶校验"，一眼看出这页是不是刚收过的那页。

**（4）SDO 下载响应**：从站处理完把响应写入**输入邮箱 SM1**，由主站读走。**主站只有得到正确响应之后才能执行下一步 SDO 操作**——这是 SDO 的请求-响应握手特征，与 PDO 的"发了就不管"正好相反。响应中 CCS = 0x03 表示下载响应，0x01 表示分段下载响应。

**（5）终止 SDO 传输**：任一方发现错误都可发起终止请求，**不需要应答**，其中含 4 字节终止代码。常用终止代码：

| 终止代码 | 含义 | 终止代码 | 含义 | 终止代码 | 含义 |
| --- | --- | --- | --- | --- | --- |
| 0x05030000 | 分段传输中翻转位无变化 | 0x05040000 | SDO 传输超时 | 0x05040001 | 命令码无效或未知 |
| 0x05040005 | 内存溢出 | 0x06010000 | 不支持对某一对象的操作 | 0x06010001 | 试图读一个只写数据对象 |
| 0x06010002 | 试图写一个只读数据对象 | 0x06020000 | 数据对象在数据字典中不存在 | 0x06040041 | 数据对象不能映射到 PDO |
| 0x06040042 | 要映射的数据对象数量和长度超过 PDO 数据长度 | 0x06040043 | 常规数据类型不兼容 | 0x06090011 | 子索引不存在 |
| 0x06090030 | 写操作时写入数据值超出范围 | 0x08000022 | 由于当前设备状态限制，数据对象不可以被传输或保存到应用程序 |  |  |

**（6）紧急事件（Emergency）**：由设备内部错误事件触发，把诊断信息发给主站；诊断事件消失之后，从站应把诊断事件和错误复位码**再发一次**。服务类型 = 1，含 **2 字节紧急错误码 + 1 字节错误寄存器 + 5 字节制造商定义错误信息**。错误码分类：

| 错误码 | 含义 | 错误码 | 含义 |
| --- | --- | --- | --- |
| 0x00xx | 错误复位或无错误 | 0x10xx | 常规错误 |
| 0x2xxx | 电流错误（21xx 设备输入端、22xx 设备内部、23xx 设备输出端） | 0x3xxx | 电压错误（31xx 主电源、32xx 设备内部、33xx 输出） |
| 0x4xxx | 温度错误（41xx 环境温度、42xx 设备温度） | 0x5xxx | 设备硬件错误 |
| 0x6xxx | 设备软件错误（61xx 内部软件、62xx 用户软件、63xx 数据） | 0x7xxx | 附加模块错误 |
| 0x8xxx | 监控（81xx 通信错误、82xx 协议错误，如 8210 PDO 由于长度错误而未被处理、8220 PDO 长度） | 0x9xxx | 外部错误 |
| 0xA0xx | **EtherCAT 状态机错误** | 0xF0xx / 0xFFxx | 附加功能 / 设备自定义 |

CoE 完全遵从 CANopen 应用层行规。CANopen 标准行规主要有 CiA401 I/O 模块、**CiA402 伺服和运动控制**、CiA403 人机接口、CiA404 测量设备和闭环控制、CiA406 编码器、CiA408 比例液压阀等。本节只讲 CiA402。

**① CiA402 伺服驱动器对象字典**：数据对象 0x6000~0x9FFF 为行规定义数据对象。**一个从站最多控制 8 个伺服驱动器，每个驱动器分配 0x800 个数据对象**：第 1 个驱动器用 0x6000~0x7FF，后续以 **0x800 偏移**递增，即对象号 = 0x6xxx + n × 0x800。基本数据对象举例：**0x6402 电机类型**（16 位：0 非标准电机、2 永磁直流电动机、3 三相永磁同步电动机、4 变频器同步电动机、5 开关磁阻电动机、6 交流异步绕线转子电动机、7 鼠笼式交流异步电动机、8 步进电动机、9 细分步进电动机、10 内装永磁无刷电动机、11 方波永磁无刷电动机、12 交流同步磁阻电动机、13 制造商定义、14 直流他励、15 直流并励、16 直流串励）、0x6403 电动机 catalog number、0x6404 电机制造商名称、0x6405 电机网址、0x6406 电机上次检测日期、0x6407 电机的服务周期、0x6503 驱动器 catalog number、0x6505 驱动器制造商网址。

**② 功率驱动设备控制状态机（本节重点）**——图示约定：**虚线框状态为可选**，细线框状态可以由从站主动切换，**粗线框内的状态必须由主站切换**。状态机按电源划成三个区：**A 区**只有低级别电源使能（也可能为使低级别电源供电而让高级别电源使能），低级别电源指 24V 等**控制部分**供电，高级别电源指 230V/380V 的**主电路**供电；**B 区**高级别供电有效，但**电动机没有扭矩输出，此时设定的指令数据应该被忽略**；**C 区**伺服设备准备好运行，**电动机有扭矩输出，设定的指令数据应该被执行**。

| 状态 | 含义 | 状态 | 含义 |
| --- | --- | --- | --- |
| Not ready to switch on | 未准备好接通电源 | Switch on disabled | 禁止接通电源 |
| Ready to switch on | 准备好接通电源 | Switched on | 已接通电源 |
| Operation enabled | 运行使能 | Quick stop active | 快速停止激活 |
| Fault reaction active | 故障反应激活 | Fault | 故障 |

16 个状态转化（0~16）：

| 转化 | 触发事件与执行操作 | 转化 | 触发事件与执行操作 |
| --- | --- | --- | --- |
| 0、1 | 上电/复位后自动转化：伺服设备自检，如果需要则执行相关初始化动作；随后自动转化启动通信功能 | 2、6、8 | 从主站获得**切断电源**命令：2 无操作；6 条件满足则切断内部级别电源；8 伺服功能失效，条件满足则切断内部级别电源 |
| 3 | 从主站获得**接通电源**命令：条件满足则接通内部级别电源 | 4 | 从主站获得**使能运行**命令：使能伺服功能，消除内部设定指令 |
| 5 | 从主站获得**停止运行**命令：停止伺服运行功能 | 7、9、10 | 从主站获得**急停或停止供电**命令：7 无操作；9 伺服功能失效，条件满足则切断高级别电源；10 条件满足则切断高级别电源 |
| 11 | 从主站获得**急停**命令：启动紧急停止功能 | 12 | 急停功能执行完成后且快速停止选项码为 1/2/3/4，或从主站收到关闭电源命令：停止伺服驱动功能，条件满足则切断高级别电源（选项码 5/6 则减速后停留在快速停止状态） |
| 13 | 出错：执行相应配置的错误反应功能 | 14 | 自动转化：停止伺服驱动功能，条件满足则隔离级别电源 |
| 15 | 设备无错误存在时执行错误条件复位；离开出错状态后从主站接收错误复位命令——**控制字中的错误复位位应该被控制设备消除** | 16 | 收到使能运行命令后执行：使能驱动功能（**不推荐使用这个转化**） |

主站通过写**控制字 0x6040** 控制状态，从站通过**状态字 0x6041** 反馈状态。分类标记：**M 必须**（Mandatory）、C 有条件（Conditional）、O 可选（Optional）、R 推荐（Recommended）。

| 控制字位 | 含义 |
| --- | --- |
| 位 0 | 接通电源（对应转化 3）；0→1 接通、1→0 切断（对应转化 2、6、8） |
| 位 1 | 使能供电（对应转化 3）；0→1 使能、1→0 停止供电（对应转化 9、10、12） |
| 位 2 | 紧急停止（只有支持急停功能时才有效，对应转化 10、11） |
| 位 3 | 使能运行（对应转化 4、16）；0→1 使能运行、1→0 停止运行（对应转化 5） |
| 位 7、8 | 错误复位（对应转化 15）/ 暂停 |
| 位 4~6、9、10、11~15 | 位 4~6 与位 9 运行模式相关；位 10 保留；位 11~15 厂商定义 |

**状态字 0x6041 的位定义**：

| 状态字位 | 含义 |
| --- | --- |
| 位 0、1、2 | 准备好接通电源 / 电源已接通 / 运行使能（高电平表示已满足） |
| 位 3、4、5、6 | 出错状态 / 电源使能状态（高电平表示高级别电源使能）/ 急停状态 / 不可接通状态 |
| 位 7、8、9、10 | 报警 / 制造商定义 / 远程（控制字被处理）/ 目标达到 |
| 位 11、12 / 位 13~15 | 内部限值有效（碰到限位开关、电流或温度过载）/ 放弃目标指令；位 13~15 运行状态定义、制造商定义 |

> 初学者最容易困惑的一点：**"控制字 + 状态字"其实是一个只有 8 个状态的握手协议**。主站发"我想要什么"（控制字），从站回"我现在实际在哪"（状态字）；主站必须**看着状态字说话**——不能直接命令它跳到 Operation enabled，只能通过给控制字让状态机自己一步步走过去。 类比电梯：你不能直接说"到 12 楼"，只能说"向上"或"向下"，电梯自己根据当前位置决定怎么走；乱按（比如还没 Switched on 就按"运行使能"）它是不会动的。

**③ CiA402 运行模式**：主站写 **0x6060** 设定运行模式，从站用 **0x6061** 表示实际运行模式，**两者数据类型都是字节型**；**0x6062** 表示驱动设备支持的运行模式，**按位定义**：位 0 pp、位 1 vl、位 2 pv、位 3 tq、位 4 hm、位 5 ip、位 6 csp、位 7 csv、位 8 cst、位 9~15 保留 / 制造商定义。

| 编码 | 运行模式（缩写 / 分类） | 编码 | 运行模式（缩写 / 分类） |
| --- | --- | --- | --- |
| -128~-1 | 制造商定义运行模式（O） | 0 | 没有分配运行模式 |
| 1 | 位置控制 pp（O） | 2 | 速度模式 vl（O） |
| 3 | 升降速度控制 pv（O） | 4 | 扭矩模式 tq（O） |
| 5、11~127 | 保留 | 6 | 回零 hm（C：支持回零功能才必备） |
| 7 | 插补位置 ip（O） | 8 | 周期同步位置 csp（C：支持位置控制功能才必备） |
| 9 | 周期同步速度 csv（C：支持速度功能才必备） | 10 | 周期同步扭矩 cst（C：支持扭矩功能才必备） |

周期性同步运行模式是 CoE 对 CiA402 的扩展，也是 EtherCAT 上做伺服最常用的三种：

- **csp 周期性同步位置模式**：位置指令由**控制主站生成**，周期性同步地把位置指令值发给驱动设备；驱动设备内部执行**位置控制、速度控制和扭矩控制**，所以多个伺服驱动装置可以**严格同步协调运动**，实现精密轮廓轨迹控制。主站也可以提供附加的速度和扭矩值实现**前馈控制**；驱动设备反馈实际位置/速度/扭矩值，并监测**跟随误差**、实现速度限制和急停。
- **csv 周期性同步速度模式**：主站周期性发速度指令；驱动设备做速度控制和扭矩控制，需要时位置环可以**通过控制主站闭合**；主站也可提供附加扭矩值实现前馈。
- **cst 周期性同步扭矩模式**：主站周期性发目标扭矩指令；驱动设备只做**扭矩控制**，并反馈实际位置/速度/扭矩值。

涉及的关键对象：607Ah 位置指令值、60FFh 速度指令值、6071h 扭矩指令值；60B0h / 60B1h / 60B2h 位置偏移量 / 速度偏移量 / 扭矩偏移量（前馈用）；6064h 实际位置值、606Ch 实际速度值、6077h 实际扭矩值、60F4h 跟随误差。三者的层级关系：**csp = 主站做轨迹规划、驱动器做三环；csv = 主站做位置环、驱动器做速度环 + 电流环；cst = 全给驱动器，主站只出扭矩。** 层级越往下放，主站负担越轻，但轨迹轮廓精度越依赖驱动器。

为了在运行状态下动态切换运行模式，要把位置指令、速度指令和扭矩指令**全部映射到 PDO 数据中**，同时把运行模式 0x6060/0x6061 也映射进去，主站和从站按实际运行模式选用 PDO 中的映射数据。切换步骤：

- **第 1~2 步**：初始化完成后运行于某一模式，主站负责更新所有与当前运行模式相关的过程数据；主站选了新模式 → RxPDO 中 0x6060 变为新选用的模式代码；
- **第 3~4 步**：从站收到 RxPDO 发现模式改变 → 进行内部模式切换，**这需要一定时间**，此时仍**反馈旧模式下的过程数据**；**主站在这个中间状态下必须同时发送旧模式和新模式的有效数据**，直到从站反馈的实际运行模式等于主站设置的模式。
- **第 5~6 步**：控制字中的模式相关位必须与 RxPDO 中的运行模式保持一致，状态字中的模式相关位必须与 TxPDO 中的实际运行模式保持一致，**包括处于中间状态时**。

示例映射（示意）：RxPDO 含 607A:00 位置指令(4B)、60FF:00 速度指令(4B)、6071:00 扭矩指令(2B)、6060:00 运行模式(1B)、6040:00 控制字(2B)；TxPDO 含 6064:00 实际位置(4B)、6077:00 实际扭矩(2B)、60F4:00 跟随误差(4B)、6061:00 实际运行模式(1B)、6041:00 状态字(2B)。

> 类比开车换挡：踩离合到挂上新挡之间有个过渡，这时候既不能断油门也不能猛加油，要"两套动作都照顾着"；等仪表（6061）确认挂上了，才切到新挡的操作方式。初学者最容易在这里出 bug：一改 6060 就立刻按新模式的字节位置去解释数据，而中间那一两毫秒驱动器还在用旧模式解读，直接飞车。

## 5.2 SoE（SERCOS over EtherCAT）

**SERCOS** 是一种高性能的数字伺服实时通信接口协议，1995 年被批准为国际标准 **IEC 61491**，内容包括通信技术和多种设备行规。**SoE** 指在 EtherCAT 协议下运行 SERCOS 定义的伺服设备行规：用 EtherCAT 通信网络和协议**操作** SERCOS 行规定义的伺服参数和控制数据，而 **EtherCAT 通信网络并不传输 SERCOS 接口链路层协议**。SoE 允许在 EtherCAT 环境中集成基于 SERCOS 设备行规的设备，内容包括 **SERCOS 状态机（通信阶段）、同步、过程数据通信和通过服务通道访问 IDN 参数**，归纳为五点：① EtherCAT 状态机与 SERCOS 通信阶段的对应；② 对 SERCOS **IDN 参数**的继承；③ SERCOS 周期性报文 **MDT（Master Data Telegram）/ AT（Drive Telegram）** 与 EtherCAT 周期性数据帧的对应；④ **取消 MST，由 EtherCAT 分布时钟实现精确同步**；⑤ SERCOS 服务通道与 EtherCAT 邮箱通信的对应，实现 IDN 访问操作。

### 5.2.2 IDN 继承

SoE 继承 SERCOS 的 **IDN** 参数定义：每个 IDN 有唯一的 **16 位标识号**，对应一个唯一的数据块，保存参数的全部信息；数据块由 **7 个元素**组成——① IDN（必备）② 名称（可选）③ 属性（必备）④ 单位（可选）⑤ 最小允许值（可选）⑥ 最大允许值（可选）⑦ 数据值（必备）。IDN 编号定义：**位 15 = S（标准数据）/ P（产品数据）**，位 12~14 = 参数组号（0~7 共 8 组），位 0~11 = 组内编号（0~4095）。

使用 EtherCAT 作为通信网络时**取消**了一些用于通信接口控制的 IDN：

| 取消的 IDN | 描述 | 取消的 IDN | 描述 |
| --- | --- | --- | --- |
| S-0-0003 | 最小 AT 发送开始时间（Tmin） | S-0-0004 | 发送到接收状态切换时间（TATMT） |
| S-0-0005 | 最小 AT 采样时间间隔 | S-0-0009 | 主站数据报文的开始地址（MDTPOS） |
| S-0-0010 | 主站数据报长度（MDTLEN） | S-0-0088 | 接收 MDT 后准备好接收 MST 报文需要的恢复时间 |
| S-0-0090 | 命令值处理时间 | S-0-0127 / S-0-0128 | 通信阶段 3 / 4 切换检查，由 EtherCAT 的 PS / SO 状态切换取代；切换失败原因分别保存在 S-0-0021 / S-0-0022 |

另外**修改**了一些 IDN 的定义：

| 原 IDN | 原功能 | 新功能 |
| --- | --- | --- |
| S-0-0006 | AT 发送开始时间（T1） | 从站内部同步信号之后应用将 AT 数据写入 ESC 存储区的时间偏移 |
| S-0-0014 / S-0-0028 / S-0-0089 | 通信接口状态 / MST 错误计数 / MDT 发送开始时间（T2） | 映射从站的数据链路层（DL）和应用层（AL）状态 / 映射从站 RX 错误计数和连接丢失计数 / 从站内部同步信号之后从 ESC 存储区得到新的 MDT 数据的时间偏移 |

| S-0-0015 | 类型：指令数据 → 反馈数据 | S-0-0015 | 类型：指令数据 → 反馈数据 |
| --- | --- | --- | --- |

| 6 | 标准类型 6：速度指令值 S-0-0036（4B），无反馈数据 | 7 | 自定义：指令数据由 S-0-0024 配置，反馈数据由 S-0-0016 配置 |

| 元素 | S-0-0024（输出 / MDT） | S-0-0016（输入 / AT） |
| --- | --- | --- |
| 0 / 1 | 输出数据最大长度 / 实际长度（Word） | 输入数据最大长度 / 实际长度（Word） |
| 2 / 3 | 指令数据映射的第 1 个 / 第 2 个 IDN | 反馈数据映射的第 1 个 / 第 2 个 IDN |

```

```

```
从站伺服状态字（16 位）

位3 命令值处理状态（1 = 伺服驱动将跟随命令数据值，0 = 已放弃）；位5、4、2、1 保留；位0 翻转位
```

**SSC**（SoE Service Channel，SoE 服务通道）由 **EtherCAT 邮箱通信**实现，用于**非周期性数据交换**，如读写 IDN 及其元素。邮箱类型 = 5 表示 SoE；邮箱数据头之后是 **4 字节 SoE 数据头**（命令字 1 字节 + 16 位 IDN + 1 字节元素标识）：

| SoE 数据头字段 | 说明 |
| --- | --- |
| 命令码 OpCode（位 0~2） | 0x01 读请求、0x02 读响应、0x03 写请求、0x04 写响应、0x05 通报、0x06 从站信息、0x07 保留 |
| 未完成（位 3）/ 出错（位 4） | 未完成：0 无后续数据帧、1 有后续数据帧；出错：0 无错误、1 发生错误（数据区有 2 字节错误码） |
| 伺服编号 Drive No（位 5~7）/ 操作元素标识 ElementFlags（1 字节） | 从站本地伺服编号；ElementFlags 按位定义，每一位为对应元素的选择位，可以同时操作多个元素，寻址结构体时该位为元素的数目 |
| IDN（2 字节）+ 有效数据 | IDN 是参数编号（分段操作时表示剩余片段），其后是有效数据；出错时为 2 字节错误码 |

**（1）SSC 读操作**：主站发起，写 SSC 读请求到从站，从站用所请求的参数 IDN 编号和数据值作为回答。**主站可以同时读多个元素，从站应该同时回答多个元素**；如果从站只支持单个元素操作，应该以所请求的第一个元素作为响应。需要读的数据长度超过邮箱容量时必须用**分段读**（一个读服务请求 + 一个或多个分段读服务响应 + 一个读服务响应）；分段响应中"未完成 = 1"表示还有后续数据，此时 **IDN 域表示后续数据的片段数**。

**（2）SSC 写操作**：主站下载数据到从站，从站以写操作的结果回答；数据超出邮箱容量时用分段写（一个或多个分段写操作 + 一个 SSC 写响应服务）。

**（3）SSC 过程命令**：过程命令是一种特殊的非周期数据，每一个过程命令都有唯一的标识号 IDN 和规定的数据元素，用于**启动伺服装置的某些特定功能或过程**。执行这些功能通常需要一段时间，**过程命令只是触发其开始**，随后它占用的服务通道立即变为可用，用以传输其他非周期数据或过程命令，而**不用等被触发的功能执行完毕**。最常用的过程命令是"**伺服装置控制的回原点过程命令 S-0-0148**"。过程命令由主站启动、从站执行：主站通过**写过程命令 IDN 的元素 7** 把"过程命令控制"发给伺服装置，用以控制过程命令的设置、启动、中断和撤消——位 2 = 撤消过程命令、位 1 = 中断过程命令、位 0 = 启动过程命令；主站通过**读过程命令 IDN 的元素 7** 得到从站的过程命令状态字——位 0 数据位有效、位 1 是否已设置、位 2 是否被启动、位 3 执行结果（1 = 尚未执行）、位 4 错误（1 = 出错不能执行）。

**基本原则**：每一个过程命令被处理后，**无论应答是执行正确还是出错，主站都应该撤消该过程命令**——把过程命令控制字的位 0 置为 0 后发给相应伺服装置。执行流程：过程命令由 SSC 写特定 IDN 发起 → 从站产生一个普通的 SSC 写响应数据，此时**服务通道空闲**，可用于传输其他非周期数据或更多过程命令 → 从站执行完过程命令后发起一个 **SSC 通报命令**（命令码 = 5）→ 主站读到通报后发出**撤销过程命令请求**，并读取过程命令状态，直到确认已被撤销。

> 类比叫外卖：过程命令像"叫个外卖然后去干别的"——你说完就可以挂电话忙自己的，饭做好了骑手才会来敲门（通报命令）。而普通的 SSC 写操作像"柜台当面办业务"，办完才能走。**这就是"过程命令不占用服务通道"的价值：一条通道能同时推进多件事。**

**（4）SSC 从站信息服务**：主要目的是**提供从站的附加信息便于系统调试和维护**。由**从站发起**，把信息数据写入**输入邮箱 SM1**，由主站读取（命令码 = 6）。

| CoE 与 SoE 的关系 | IEC 61800-7 把行规映射到网络：CoE 用 EtherCAT 跑 CANopen 的 CiA402，SoE 用 EtherCAT 跑 SERCOS 行规（不传 SERCOS 链路层） |
| 对象字典五大区间 | 0x0000~0x0FFF 数据类型、0x1000~0x1FFF 通信对象、0x2000~0x5FFF 制造商、0x6000~0x9FFF 行规、0xA000~0xFFFF 保留 |
| 三层 PDO 映射链 | 数据对象 → PDO 映射对象（0x1600/0x1A00）→ PDO 分配对象（0x1C1x）→ SM 通道 → 帧中逻辑地址 |
| SDO 三种传输方式 | 快速（≤4 字节）、常规（≤邮箱容量 − 16）、分段（超容量，最多 7 字节/段） |
| SDO 与 PDO 的本质差别 | SDO 是请求-响应握手，必须等到正确响应才能做下一步；PDO 是"发了就不管"的周期数据 |
| 紧急事件 | 设备的"报警器"：内部错误触发上报，错误消失还要再发一次复位码，错误码按 0x2xxx 电流、0x3xxx 电压等分类 |
| CiA402 状态机与控制字/状态字 | 主站看着状态字发控制字，一步步走完 8 个状态、16 个转化；B 区忽略指令、C 区才执行指令 |
| csp / csv / cst 的层级差异 | csp 主站规划轨迹、驱动器做三环；csv 主站做位置环；cst 主站只出扭矩——越往下放，主站越轻松 |
| 切换运行模式必须过渡 | 中间态要同时发新旧两种模式的有效数据，直到 0x6061 反馈等于 0x6060 设定值 |
| SoE 复用 SERCOS 的 IDN | IDN 是 16 位唯一标识，数据块含 7 个元素；EtherCAT 取消了若干通信接口类 IDN，并改写了几个的定义 |
| 取消 MST | SoE 不用 SERCOS 的主站同步报文 MST，改由 **EtherCAT 分布时钟**实现精确同步 |
| SSC 过程命令 | 只触发功能开始，服务通道立刻空闲，完成后用"通报"命令回报，主站再撤消过程命令 |
