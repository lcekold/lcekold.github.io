# 一、使用前要准备什么？

在开始用 EtherCAT 之前，先准备好这几样东西：

* **硬件**：支持 EtherCAT 的设备（PLC 作为主站、伺服/变频器/远程 IO 作为从站）、标准网线（超五类及以上）。从站之间**不需要交换机**，一台台串着连就行。
* **拓扑规划**：想清楚从站怎么排（一般就按一条线串下去）。EtherCAT 大多**不需要 IP 地址**，也就没有“配 IP”这一步，这是它和 Ethernet/IP 最大的不同。
* **ESI 文件（EtherCAT 从站信息文件）**：这是从站设备的“说明书”，描述这台从站有哪些对象、能提供哪些过程数据（PDO）、参数怎么读写。它是 `.xml` 格式，**向设备厂商索取**对应型号的 ESI 文件，主站软件导入后会用它识别和配置从站。

> 一句话：EtherCAT 不需要配 IP，你把从站**一台台串起来**，再让主站“认”到它们，剩下的就是配数据。

# 二、整个流程：从配置到运行

无论采用何种方案，使用 EtherCAT 通常都遵循以下步骤：

1. **准备硬件**：一台可作为主站的设备（如工控机、PLC）和所需的 EtherCAT 从站设备（如伺服驱动器、I/O 模块），并用网线将它们连接起来。
2. **选择主站方案**：根据项目需求，选择一种 EtherCAT 主站实现方案（见第七节）。
3. **安装与配置从站**：将从站设备接入网络，并导入其 **ESI** 文件。ESI 文件是从站的“身份证”，描述了其所有功能和特性，主站需要它来正确识别和配置从站。
4. **配置主站与建立映射**：在主站软件中扫描并添加从站设备，然后将主站中的过程数据变量与从站提供的输入/输出数据一一对应起来。
5. **编写应用与运行**：在主站端编写应用程序（如 PLC 逻辑或 C/Python 程序），通过读写映射好的变量来控制从站，最后启动主站开始周期性的数据交换。

# 三、搞懂两个角色：Master（主站）和 Slave（从站）

使用 EtherCAT，核心是理解它**主站（Master）** 和**从站（Slave）** 的架构：

* **Master（主站，大脑）**：通常是 PLC 或运动控制器，是**唯一**发起通信、产生数据帧的角色。它决定周期、管理整个环上的所有从站。
* **Slave（从站，手脚）**：伺服驱动器、I/O 模块、变频器、传感器等，是“被动处理”帧的设备，负责执行并反馈。每个从站带**两个网口（IN/OUT）**，方便一台台串起来。

典型组合就是：**PLC 当 Master，伺服/变频器当 Slave。**

# 四、快速上手：把 PLC 和一台伺服连起来

下面以“PLC（Master）和一台伺服（Slave）”为例，跑通一条 EtherCAT 连接。

## 4.1 接线（串联）

1. 用网线把 PLC 的**主站网口**连到第一台从站的 **IN** 口。
2. 第一台从站的 **OUT** 口连到下一台的 **IN** 口。
3. 一台台串下去；如果想要冗余环，最后一台从站的 OUT 口再连回主站的第二个网口。

```
主站PLC ──>[IN] 伺服（OUT）──>[IN] 变频器（OUT）──>…（→ 可选连回主站组环）
```

> EtherCAT **不需要 IP**，也没有“配 IP”这一步；网线上一头接一头，认的就是物理位置。

## 4.2 导入 ESI 文件

在 PLC 的编程软件里导入伺服的 `.xml`（ESI）文件。导入后，软件就能识别这台伺服的型号、对象、过程数据槽位，不用手动一个个去猜。如果软件里已经自带该品牌库，可跳过这一步。

## 4.3 添加从站（Slave）设备并扫描

1. 在工程的 EtherCAT 配置（设备树）里，右键“扫描从站/添加从站”。
2. 软件通常会**自动扫描**出环上连接的从站；若扫描不到，就手动按接线顺序把对应型号添加进设备树。

## 4.4 设置过程数据（PDO）与周期

| 参数 | 说明 | 常用建议 |
| ---- | ---- | ---- |
| **过程数据（PDO）** | 周期性交换的 I/O 数据，如速度给定、实际位置、状态字 | 按 ESI/从站手册勾选需要的槽位并映射 |
| **周期时间（Cycle Time）** | 主站每个周期刷新一次环上数据 | 普通控制 1~4ms；运动控制可以到毫秒级甚至更低，越小越好（注意别超过从站极限） |
| **分布式时钟（DC）** | 主站同步所有从站时钟，保证采集/输出纳秒级同步 | 多轴同步控制时建议开启 |

## 4.5 分配变量并下载运行

1. 把 PDO 的数据映射成 PLC 里的变量（普通内存区或标签）。
2. 编译、下载到 PLC 并运行。
3. 观察主站状态是否变成 **OP（Operational，运行态）**。若为 OP，说明连接已建立，可以开始读写数据了。

# 五、两类数据怎么用？

EtherCAT 里有两类数据，用途完全不同：

| | 过程数据（PDO） | 邮箱数据（SDO / Mailbox） |
| ---- | ---- | ---- |
| **用途** | 实时控制数据：启停、速度、位置、状态 | 配置、参数读写、诊断 |
| **方式** | 周期性、批量地交换，自动刷新 | 一问一答，需要时才发一次 |
| **速度** | 快，实时性极强 | 相对慢一些，但更可靠、灵活 |

* **什么时候用 PDO？** 需要“一直、实时”更新的数据，比如速度给定、位置、实际转速、I/O 状态。
* **什么时候用 SDO（邮箱）？** 偶尔才做一次的操作，比如改参数、读故障码、下发初始配置。邮箱通信也用于主站“识别”和“配置”从站。

# 六、打通后如何读写数据？

连接建立（变为 OP）之后，对 PLC（Master）来说，从站的数据就像普通变量一样。注意 PDO 的方向命名（以从站为参照）：

* **RxPDO（主站→从站）**：主站**写给**从站的数据，用于**控制**，比如“写入速度给定值”“置位启动命令”。
* **TxPDO（从站→主站）**：从站**回报**给主站的数据，用于**监控**，比如“读实际转速”“读状态字判断是否就绪”。

在编程层面，你**不需要**再关心数据是怎么打包和传过去的，只需要操作映射好的变量即可。这就是 EtherCAT 相比自己写串口协议最大的方便之处。

# 七、主站的实现：三种主流方案

EtherCAT 主站通常是一台运行了特定软件或系统的计算设备，主要有以下三种实现方式：

## 方案一：专用 PLC 软件（最成熟，适合工程应用）

这是工业现场最常见的方式。你可以在支持 EtherCAT 的 PLC 编程软件中完成所有配置和编程。

* **常见软件**：**TwinCAT (Beckhoff)**、**CODESYS**、**Sysmac Studio (欧姆龙)** 等。
* **流程示例（以 CODESYS 为例）**：
  1. **建工程**：新建一个 CODESYS 标准工程。
  2. **装 ESI**：通过 `Tools -> Device Repository` 安装从站设备的 ESI 文件。
  3. **添主站**：在工程中 `Add Device`，选择 `EtherCAT Master` 添加主站。
  4. **扫从站**：扫描或手动添加连接到主站下的从站设备。
  5. **写逻辑**：编写 PLC 程序，控制映射好的变量。
  6. **下程序**：将工程下载到 PLC 控制器中运行。

## 方案二：开源主站协议栈（最灵活，适合深度定制）

适合需要高度定制，或希望将 EtherCAT 主站功能集成到自有硬件/软件产品中的开发者。

* **IgH EtherCAT Master**：Linux 下高性能开源方案，运行于 Linux 内核态，实时性极佳，但需要在 Linux-RT 实时内核环境下编译和配置。
* **SOEM（Simple Open EtherCAT Master）**：轻量级、跨平台开源方案，代码简洁，易于移植到 Windows、Linux 或各种 RTOS 上，适合快速原型验证或资源受限的嵌入式主站。

## 方案三：商业协议栈（最省心，适合产品级应用）

如果你在开发一款需要稳定、可靠 EtherCAT 主站功能的商业产品，购买商业协议栈是更高效的选择。它们通常提供更好的技术支持、更完整的协议功能（如支持各种 CoE、FoE 等）和经过认证的稳定性。代表有 **Acontis EC-Master** 等。

# 八、从站的实现：硬件核心 ESC 芯片

一个设备要想成为 EtherCAT 从站，其硬件核心是集成一个 **EtherCAT 从站控制器（ESC）** 芯片。这个专用芯片负责在硬件层面处理 EtherCAT 通信协议。

市面上常见的 ESC 芯片解决方案包括：

* **独立 ESC 芯片**：如 **Microchip LAN9253**、**Beckhoff ET1100/ET1200** 等。
* **集成 ESC 的 MCU**：如 **瑞萨 RZ/T2H**、**TI TMS320F2838x** 等。

如果你需要自己开发 EtherCAT 从站设备，就需要基于这些芯片，并移植相应的从站协议栈代码（如 **Beckhoff 的 SSC（从站协议栈代码）** 工具）。

# 九、常见问题排查

| 现象 | 可能原因 | 处理办法 |
| ---- | ---- | ---- |
| 扫描不到从站 | 接线顺序错 / 线没插好 / 从站未上电 | 核对 IN/OUT 连接和供电；确认主站网口正确 |
| 状态不是 OP | PDO 映射没配好 / 从站未使能 / 安全回路未就绪 | 查看从站报警码，确认使能条件；核对 PDO 映射 |
| 周期抖动大 | 周期时间设得太小 / 网线、连接质量差 | 适当调大周期；检查网线和接头 |
| 多轴不同步 | 未开启分布式时钟（DC） | 在多轴同步项目中开启 DC 同步 |
| 数据乱 | ESI 型号对错 / 数据类型、字节序不匹配 | 核对 ESI 与设备型号；按手册调整 PDO 映射 |

> EtherCAT 因为在实时环里**不用交换机、不依赖 IP**，也没有 TCP/UDP 端口，所以抓包排障的思路和 Ethernet/IP 不一样。若需要底层分析，用 Wireshark 看 **Ethernet 帧 EtherType = 0x88A4** 的报文即可（正常环上应能看到主站周期性发出的帧）。

# 十、小结

总的来说，使用 EtherCAT，你既可以像使用传统 PLC 一样，通过 **CODESYS、TwinCAT** 等软件快速搭建一个稳定可靠的工业控制系统；也可以作为开发者，利用 **SOEM、IgH** 等开源协议栈，将 EtherCAT 主站功能集成到自己的软件或硬件产品中。

**对刚开始学习的你，最推荐的路径是**：下载一个 **TwinCAT** 或 **CODESYS** 的试用版，在软件中尝试添加一个虚拟的 EtherCAT 主站和从站，并进行 IO 映射。通过这种方式，你可以零成本、直观地理解 EtherCAT 的配置和数据交换流程。
