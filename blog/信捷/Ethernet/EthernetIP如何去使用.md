# 一、使用前要准备什么？

在开始用 Ethernet/IP 之前，先准备好三样东西：

* **硬件**：支持 Ethernet/IP 的设备（PLC、伺服、变频器、传感器等）、标准网线（超五类及以上）、交换机或路由器。
* **网络（IP 地址）**：把要通信的设备规划到**同一个网段**，并且每个设备的 IP 地址**不能重复**。建议养成先规划 IP 再上电的习惯，比如：

| 设备 | IP 地址 |
| ---- | ---- |
| PLC（主站） | 192.168.1.10 |
| 伺服 | 192.168.1.20 |
| 变频器 | 192.168.1.21 |

* **EDS 文件（电子数据手册）**：这是从站设备的“说明书”，里面用标准格式描述了这台设备有哪些对象、数据是什么格式、能提供哪些 I/O。**向设备厂商索取**对应型号的 `.eds` 文件，后面配置主站时要用。

> 一句话：Ethernet/IP 用的就是普通以太网线和 TCP/IP。**网络通了，剩下的就是“认设备”和“配数据”。**

---

# 二、搞懂两个角色：Scanner（主站）和 Adapter（从站）

Ethernet/IP 通信里，设备分成两类角色：

* **Adapter（适配器，从站）**：是**提供** I/O 数据的设备，比如伺服、变频器、远程 IO、传感器。它被动响应连接。
* **Scanner（扫描器，主站）**：是**主动发起连接、读取和写入**数据的设备，通常就是 PLC。它按固定周期去“扫描”从站。

典型组合就是：**PLC 当 Scanner，伺服/变频器当 Adapter。**

# 三、快速上手：把 PLC 和一台伺服连起来

下面以“PLC（Scanner）和一台伺服（Adapter）”为例，跑通一条 Ethernet/IP 连接。

## 3.1 接线 + 配 IP

1. 用网线把 PLC 和伺服接到同一台交换机上。
2. 分别给两者设置同一网段且唯一的 IP 地址（见第一节），先在各自软件/面板里确认 IP 配置正确。

## 3.2 导入 EDS 文件

在 PLC 的编程软件里，通过菜单“添加 EDS 文件”把伺服的 `.eds` 文件导入进来。导入后，软件就知道这台伺服有哪些参数和数据槽位，不用你手动一个个去猜。

## 3.3 添加从站（Adapter）设备

1. 在工程的 IO 配置（或 EtherNet/IP 配置）里新建一个 Ethernet/IP 从站。
2. 选中刚才导入的伺服型号，填写它的 IP 地址。

## 3.4 设置连接参数

创建连接时重点设置这几个参数：

| 参数 | 说明 | 常用建议 |
| ---- | ---- | ---- |
| **RPI（请求包间隔）** | Scanner 多久去取一次 I/O 数据，单位毫秒 | 普通控制 10~20ms，运动控制越小越好（注意别超过设备极限） |
| **连接超时** | 超过多久收不到数据就判定断线 | 通常取 RPI 的 4 倍及以上 |
| **O→T（出站）数据** | 主站写给从站的数据，如“速度给定”“启停命令” | 按 EDS/从站手册配置 |
| **T→O（入站）数据** | 从站回报给主站的数据，如“实际转速”“状态字” | 按 EDS/从站手册配置 |

## 3.5 分配变量并下载运行

1. 把 O→T、T→O 的数据映射成 PLC 里的变量（普通内存区或标签）。
2. 编译、下载到 PLC 并运行。
3. 观察连接状态是否变成 **Running / Connected**。绿灯或状态字正常，说明连接已建立，可以开始读写数据了。

# 四、两种消息怎么用？

Ethernet/IP 里有两类消息，用途完全不同：

| | 隐式消息（I/O） | 显式消息（显式） |
| ---- | ---- | ---- |
| **用途** | 实时控制数据：启停、速度、位置、状态 | 配置、参数读写、诊断、连接建立 |
| **协议/端口** | UDP，默认 2222 | TCP，44818 |
| **方式** | 连接建立后，定时地、批量地交换，主站和从站都按周期收发 | 一问一答，需要时才发一次 |
| **速度** | 快，低开销 | 慢一些，但更可靠 |

* **什么时候用隐式消息？** 需要“一直、实时”更新的数据，比如速度给定、位置、实际转速、I/O 状态。
* **什么时候用显式消息？** 偶尔才做一次的操作，比如改参数、读故障码、下发配置。显式消息也用于**建立**隐式连接的初始握手。

# 五、打通后如何读写数据？

连接建立之后，对 PLC（Scanner）来说，从站的数据就像普通变量一样：

* **写数据（控制从站）**：直接写 O→T 里映射的变量，比如“写入速度给定值”“置位启动命令”。
* **读数据（监控从站）**：直接读 T→O 里映射的变量，比如“读实际转速”“读状态字判断是否就绪”。

在编程层面，你**不需要**再关心数据是怎么打包和通过网络传过去的，只需要操作映射好的变量即可。这就是 Ethernet/IP 相比自己写串口协议最大的方便之处。

# 六、常见问题排查

| 现象 | 可能原因 | 处理办法 |
| ---- | ---- | ---- |
| 连接不上 | IP 不在同一网段 / IP 冲突 | 用 `ping` 测试互通，核对 IP 规划 |
| 连上但数据乱 | EDS 型号对错 / 数据类型或字节序不匹配 | 核对 EDS 与设备型号；按手册调整数据映射 |
| 偶发断线 | RPI 设置太小 / 网线、交换机质量差 | 适当调大 RPI 和超时；检查网线和交换机 |
| 状态字一直不 Ready | 从站未使能 / 安全回路未就绪 | 查看从站报警码，确认使能条件 |
| 无法定位问题 | — | 用 Wireshark 抓包：看 2222（UDP，隐式）和 44818（TCP，显式）端口有无正常报文 |

> 抓包时，一个 Ethernet/IP 报文从外到内依次是：以太网头部 → IP 头部 → TCP/UDP 头部（看端口区分显式/隐式）→ CIP 封装头 → CIP 数据段。

---

# 七、小结

Ethernet/IP 用起来其实就三步：**把网络连通 → 让主站（Scanner）认识从站（Adapter）→ 建立连接并交换 I/O 数据**。只要 IP 规划好、EDS 拿对、RPI 设合理，剩下的就是像读写普通变量一样操纵数据了。
