# PLC 开发完整流程详解

## 一、概述

PLC（Programmable Logic Controller，可编程逻辑控制器）开发不是单纯的"写程序"，而是一套从需求分析到现场调试再到后期维护的**系统工程**。本文按照实际工程项目的时间线，以**信捷 XC 系列 PLC + XDPPro 编程软件**为主线，梳理 PLC 开发的完整流程。

---

## 二、总体流程概览

```
┌─────────────┐
│  ① 需求分析  │  明确控制要求、IO 点数、工艺流程
└──────┬──────┘

┌─────────────┐

└──────┬──────┘

│  ③ 硬件组态  │  软件中添加 CPU、IO 模块、配置参数

│  ④ 程序编写  │  编写逻辑、算法、通信、报警等程序
└──────┬──────┘
       ▼
┌─────────────┐
│  ⑤ 离线仿真  │  在软件中模拟运行，验证逻辑正确性

└─────────────┘
```

## 三、各阶段详细说明

### ① 需求分析

这是最重要但最容易忽视的一步。需求没搞清楚就写程序，后期返工成本极高。

#### 需要确认的内容

| 项目 | 具体内容 |
|------|---------|
| **控制对象** | 控制什么设备？电机、气缸、阀门、变频器、伺服？ |
| **工艺流程** | 设备的动作顺序、联锁条件、安全保护 |
| **IO 点数** | 输入：传感器、按钮、限位开关数量<br>输出：继电器、接触器、指示灯数量 |
| **信号类型** | DI/DO（数字量）、AI/AO（模拟量）、脉冲、通信 |
| **通信需求** | 是否需要与上位机、HMI、变频器、其他 PLC 通信 |
| **安全等级** | 是否需要安全 PLC？急停回路设计？ |
| **环境条件** | 温度、湿度、粉尘、电磁干扰等 |

#### 输出文档

- **IO 表**（信号名称、地址、类型、注释）
- **工艺流程描述**（文字或时序图）
- **设备清单**（初步的传感器、执行器选型）

### ② 方案设计

#### 2.1 PLC 选型

| 品牌 | 常见系列 | 适用场景 |
|------|---------|---------|
| **西门子** | S7-1200 / S7-1500 / S7-200 SMART | 中大型项目，国内主流 |
| **三菱** | FX3U / FX5U / L 系列 | 小型设备、成本敏感 |
| **欧姆龙** | CP1H / NJ / NX 系列 | 电子行业、运动控制 |
| **施耐德** | M200 / M221 / M241 | 中小型项目 |
| **汇川** | H3U / H5U | 国产替代，性价比高 |
| **信捷** | **XC 系列**（XC1/XC2/XC3/XC5） | **小型设备主力**，性价比极高，IO 点数 14~60 点 |
| **信捷** | XD / XL 系列 | XD 增强型，XL 薄型，功能更强 |

##### 信捷 XC 系列选型指南

```
XC 系列选型要点：

XC1 系列  ── 经济型，IO 14~30 点，无网口
            → 简单逻辑控制，成本敏感项目

XC2 系列  ── 基本型，IO 14~48 点，带两个串口
            → 常规设备控制，支持 Modbus 通信

XC3 系列  ── 增强型，IO 14~60 点，支持高速脉冲
            → 需要脉冲控制步进/伺服的项目

XC5 系列  ── 高性能型，IO 14~60 点，3 路脉冲输出
            → 多轴运动控制，需要较高运算性能
```

XC 系列型号命名规则：

```
XC3-32T-E        ← 举例
││  ││ │
││  ││ └── E=AC 电源（无 E 为 DC 24V）
││  │└─── T=晶体管输出（R=继电器输出，RT=继电器+晶体管混合）
││  └──── 32=总 IO 点数（16 输入 + 16 输出）
│└─────── 3=系列（1/2/3/5）
└──────── XC 系列

常见型号速查：
XC1-14R-E    14点(8入/6出)   继电器输出   AC电源
XC3-24T-E    24点(14入/10出) 晶体管输出   AC电源
XC3-32T-E    32点(16入/16出) 晶体管输出   AC电源
XC5-48T-E    48点(24入/24出) 晶体管输出   AC电源
XC3-60T-E    60点(36入/24出) 晶体管输出   AC电源
```

#### 选择依据

```
PLC 选型优先级：
① IO 点数：当前点数 + 20%~30% 余量
② 程序容量：预估程序大小
③ 通信协议：Modbus RTU（XC 系列常用）、自由口通信、CANlink（XC5 系列支持）
④ 运动控制：是否需要轴控制、插补
⑤ 响应速度：扫描周期要求
⑥ 品牌偏好/客户指定
```

#### 2.2 电气原理图设计

需要同电气工程师配合，完成：

- **主电路**：电源、断路器、接触器、热继电器、电机
- **控制电路**：PLC 数字量/模拟量接线
- **安全回路**：急停按钮、安全继电器、门锁
- **通信网络**：总线拓扑、IP 地址规划

### ③ 硬件组态

在 PLC 编程软件中**建立一个和实际硬件完全一致的虚拟PLC**。

#### 主流编程软件

| PLC 品牌 | 编程软件 |
|----------|---------|
| **信捷 XC 系列** | **XDPPro**（推荐，支持全系列 XC） |
| 信捷 XD/XL 系列 | XDPPro 或 AutoShop |
| 西门子 S7-1200/1500 | TIA Portal（博途） |
| 西门子 S7-200 SMART | STEP 7-MicroWIN SMART |
| 三菱 FX 系列 | GX Works2 / GX Works3 |
| 欧姆龙 | Sysmac Studio / CX-One |
| 施耐德 | EcoStruxure Machine Expert / SoMachine |
| 汇川 | AutoShop |

#### 硬件组态步骤

信捷 XC 系列为**一体机**设计（CPU + IO 集成在同一机体上），硬件组态比模块式 PLC 简单很多：

1. **新建工程** → 选择 PLC 系列（XC）、具体型号（如 XC3-32T-E）
2. **配置本体 IO** → 软件自动识别本体输入输出地址
3. **配置扩展模块**（如有）→ BD 板、AD/DA 模块、扩展 IO 模块
4. **配置通信参数** → 串口参数（波特率、校验位）、通信协议（Modbus、自由口）
5. **配置高速脉冲参数** → 脉冲输出模式、加减速时间

```
XDPPro 新建工程示例：
┌──────────────────────────────────────────┐
│  [新建工程]                              │
│  ├── 系列选择：XC                        │
│  ├── 型号选择：XC3-32T-E                │
│  ├── 工程名称：包装机控制               │
│  └── 编程语言：梯形图                    │
├──────────────────────────────────────────┤
│  工程管理树                              │
│  ├── 主程序（MAIN）                     │  ← 主循环
│  ├── 子程序0（SBR0） ~ 子程序7（SBR7）  │  ← 子程序
│  ├── 中断程序0（INT0） ~ 中断程序3（INT3）│  ← 中断
│  ├── 变量表                             │
│  └── 数据块                             │
└──────────────────────────────────────────┘
```

### ④ 程序编写

#### 4.1 编程语言

| 语言 | 缩写 | 适用场景 |
|------|------|---------|
| 梯形图 | **LD** | 逻辑控制、启停、互锁（最常用） |
| 功能块图 | **FBD** | 模拟量运算、PID、信号处理 |
| 结构化文本 | **ST** | 复杂算法、数据处理、数组运算 |
| 顺序功能图 | **SFC** | 步进控制、顺序流程（如自动线） |
| 指令表 | **IL** | 简单逻辑，已逐渐淘汰 |

> 实际项目中：**LD 占 70%**（逻辑控制），**FBD 占 20%**（模拟量/运算），**ST 占 10%**（复杂算法 / 通信处理，看个人习惯）。

> **信捷 XC 系列在 XDPPro 中主要使用梯形图（LD）和指令表（IL）编程**，新版本 XDPPro 也支持 FBD 和 SFC。

#### 4.2 程序结构（以信捷 XC 系列 + XDPPro 为例）

```
XC 系列程序结构：
┌────────────────────────────────────────────┐
│  主程序（MAIN）            ← 每个扫描周期执行一次  │
│  ├── 网络1：启停逻辑                       │
│  ├── 网络2：互锁保护                       │
│  ├── 网络3：调用子程序（CALL SBR0）       │
│  ├── 网络4：调用子程序（CALL SBR1）       │
│  └── 网络5：输出刷新                       │
├────────────────────────────────────────────┤
│  子程序0（SBR0） — 电机控制                │
│  子程序1（SBR1） — 传感器信号处理          │
│  子程序2（SBR2） — 通信处理                │
│  子程序3（SBR3） — 报警处理                │
├────────────────────────────────────────────┤
│  中断程序0（INT0） — 高速计数中断          │
│  中断程序1（INT1） — 定时中断              │
└────────────────────────────────────────────┘
```

> **注意**：XC 系列不支持像西门子 TIA Portal 那样的自由命名 OB/FC/FB，程序按 MAIN / SBR0~7 / INT0~3 的固定结构组织。通过注释来区分不同功能模块。

#### 4.3 编程规范要点

| 规范 | 说明 |
|------|------|
| **变量命名** | 清晰可读，如 `M0_Motor1_Start`, `M10_Fault_Reset` |
| **注释** | 每个网络/逻辑块都要写注释，说明"为什么这么做" |
| **模块化** | 不同功能写到不同的 SBR 子程序中，不要一个 MAIN 写完 |
| **软元件规划** | XC 寻址有固定规则，提前规划好地址分配 |
| **版本控制** | 程序文件使用 Git 或至少加版本号备份 |
| **安全原则** | 电机正反转必须有硬件互锁 + 软件互锁双重保护 |

##### 信捷 XC 系列软元件（寄存器）一览

XC 系列的编程本质是对各类软元件进行逻辑操作。以下是最常用的软元件：

| 软元件 | 名称 | 范围（以 XC3 为例） | 说明 |
|--------|------|-------------------|------|
| **X** | 输入继电器 | X0 ~ X77（八进制） | 本体输入点，**只读** |
| **Y** | 输出继电器 | Y0 ~ Y77（八进制） | 本体输出点，**读写** |
| **M** | 辅助继电器 | M0 ~ M7999 | 中间变量，相当于内部标志位 |
| **S** | 状态继电器 | S0 ~ S4095 | 步进/顺控编程专用 |
| **T** | 定时器 | T0 ~ T511 | 延时控制 |
| **C** | 计数器 | C0 ~ C511 | 计数控制 |
| **D** | 数据寄存器 | D0 ~ D9999 | 16 位数据存储 |
| **TD** | 32 位定时器 | TD0 ~ TD63 | 长定时 |
| **HSC** | 高速计数器 | HSC0 ~ HSC7 | 高速脉冲计数 |
| **PLC** | PLC 状态字 | PLC → M 等 | 读取 PLC 自身状态 |

> **X 和 Y 的地址都是八进制的**（0~7, 10~17, 20~27...），这是新手最容易搞错的地方。例如 X10 后面是 X11 而不是 X8。

##### 地址规划示例（32 点 PLC）

```
XC3-32T-E（16入 + 16出）

输入地址规划（X，八进制）：
X0  ~ X7       ← 本体第 1 组输入（8 点）
X10 ~ X17      ← 本体第 2 组输入（8 点）

输出地址规划（Y，八进制）：
Y0  ~ Y7       ← 本体第 1 组输出（8 点）
Y10 ~ Y17      ← 本体第 2 组输出（8 点）

内部软元件规划：
M0  ~ M99      ← 设备状态标志
M100~ M199     ← 报警标志
M200~ M299     ← 模式选择标志
D0  ~ D99      ← 工艺参数
D100~ D199     ← 传感器数据
D200~ D299     ← 通信数据缓冲区
```

#### 4.4 典型逻辑框架

```
信捷 XC 系列每个扫描周期：
┌─────────────────────────────────────────┐
│  ① 读取输入（X 区刷新）                  │
│     → 读取 X0~Xn 的物理输入信号          │
├─────────────────────────────────────────┤
│  ② 执行 MAIN 程序                        │
│     → 逐行扫描梯形图网络                  │
│     → 遇到 CALL 指令则跳入子程序执行      │
│     → 子程序执行完返回 MAIN 继续          │
├─────────────────────────────────────────┤
│  ③ 写入输出（Y 区刷新）                  │
│     → 将 Y0~Yn 的状态输出到物理端口       │
├─────────────────────────────────────────┤
│  ④ 执行系统自检/通信处理                  │
│     → 检测通信端口、刷新定时器/计数器      │
└─────────────────────────────────────────┘

注意事项：
- XC 系列**不支持中断嵌套**。执行中断时如果又来一个中断，按优先级排队
- 程序中不要出现双线圈（同一个 Y 或 M 在两个地方被赋值），逻辑会以最后执行的为准
- CALL 指令最多支持 8 层嵌套
```

#### 4.5 信捷 XC 梯形图编程示例

以下是 XDPPro 中一个电机正反转控制的梯形图逻辑描述：

```
示例：电机正反转控制

   ┌── 正转启动 ──┐
   X0    X1    M0          Y0
──┤├──┤├──┤├────────────(  )── 正转接触器
         │  Y0
         └──┤├── 自锁

   ┌── 反转启动 ──┐
   X2    X1    M0          Y1
──┤├──┤├──┤├────────────(  )── 反转接触器
         │  Y1
         └──┤├── 自锁

   ┌── 软件互锁 ──┐
   Y0                     Y1
──┤├──┤╱────────────────────  串 Y0 的常闭触点到 Y1 回路
                              Y1 回路也要串 Y0 的常闭

   ┌── 急停标志 ──┐
   X3                     M0
──┤├────────────────────(  )──  常闭急停信号
```

**说明**：
- `X0` = 正转启动按钮，`X1` = 停止按钮，`X2` = 反转启动按钮
- `X3` = 急停输入（接 NC 常闭触点，断开=急停按下）
- `Y0` = 正转接触器，`Y1` = 反转接触器
- `M0` = 急停标志位
- **正反转必须双重保护**：软件互锁（梯形图中串常闭）+ 硬件互锁（接触器机械互锁）

#### 4.6 XDPPro 编程常用技巧

| 技巧 | 说明 |
|------|------|
| **使用符号表** | 在 XDPPro 变量表中给 X/Y/M/D 赋值符号名，程序中显示为符号而非绝对地址 |
| **用 M 做中间继电器** | 复杂条件用 M 做中间过渡，避免梯形图过于冗长 |
| **SET/RST 代替自锁** | 用 SET 指令置位、RST 指令复位，比自锁电路更清晰 |
| **ALT 交替输出** | ALT 指令实现单按钮启停（按一次通，再按一次断） |
| **PLS 脉冲指令** | PLS 生成一个扫描周期的脉冲，常用于触发沿信号 |
| **CALL 调用子程序** | 用 CALL 指令将不同功能模块化，便于维护 |

#### 4.7 信捷 XC 通信配置（Modbus RTU）

XC 系列最常用的通信方式是 **Modbus RTU**，通过本体自带的串口实现。

```
XDPPro 中配置 Modbus RTU 通信：

① 工程管理树 → 双击"通信配置"
② 选择串口号（COM1 / COM2）
③ 设置参数：
   波特率：9600 / 19200 / 38400 / 115200
   数据位：8
   校验位：无 / 偶校验 / 奇校验
   停止位：1 / 2
④ 选择协议：Modbus RTU 或 自由口协议

XC 做主站时（读取变频器数据）：
  ┌─────────────────────────────────────────┐
  │  梯形图中调用 Modbus 指令：              │
  │  MODR K1 H03E9 D100 K2    ← 读地址 1001 │
  │        │   │    │    │      的数据到 D100 │
  │        │   │    │    └── 读取数据长度    │
  │        │   │    └─────── 目标 D 寄存器    │
  │        │   └───────────── 从站寄存器地址  │
  │        └───────────────── 从站站号        │
  │                                          │
  │  MODW K1 H1000 D200 K1  ← 写数据到从站   │
  └─────────────────────────────────────────┘

XC 做从站时（与 HMI 通信）：
  在通信配置中设置为 Modbus 从站模式
  站号与 HMI 端设置的站号保持一致
  HMI 直接通过 Modbus 读写 XC 的 X/Y/M/D 软元件
```

> **注意**：XC3 及以上系列有两个串口，COM1 接 HMI，COM2 接变频器/仪表是常见配置。
> XC1 系列只有一个串口，需要扩展 BD 板增加第二个通信口。

#### 4.8 程序下载与在线监控

XDPPro 下载程序到 XC 系列 PLC 的流程：

```
① 连接 PLC
   └── 编程电缆：USB 转 422/485 专用电缆
   └── 或使用以太网（XC3 以上带网口的型号）

② 通信测试
   └── XDPPro → 通信 → 通信测试
   └── 确认软件能识别到 PLC 型号

③ 下载程序
   └── 编译（检查语法错误）
   └── 下载：点击"下载"按钮
   └── 选择：程序 + 参数 + 注释（根据需要）

④ 在线监控
   └── 点击"监控"按钮
   └── 梯形图中：绿色线 = 导通，蓝色线 = 不导通
   └── 可以实时看到 X/Y/M 的通断状态
   └── 鼠标悬停在软元件上可查看当前值

⑤ 强制/修改
   └── 在线修改当前值（调试时用）
   └── 在线修改程序（修改后 PLC 不停机）
   └── 注意：修改后要执行"完整编译下载"才能永久保存
```

### ⑤ 离线仿真

在程序下载到真实 PLC 之前，先在电脑上模拟运行。

- **XDPPro 仿真模式**：XDPPro 提供**在线仿真**功能，在编程软件中通过软元件状态强制来模拟输入信号，观察程序运行结果
- **TIA Portal 仿真（S7-PLCSIM）**：可以在电脑上模拟运行 S7-1200/1500 程序
- **GX Works 仿真**：三菱 GX Simulator
- **限制**：仿真无法模拟真实的硬件接线、通信延迟、输入信号抖动

> **XC 系列实际调试技巧**：信捷 XC 系列不支持像西门子那样的全离线仿真。调试时通常采用"**程序下载 → 在线监控 → 手动强制输入 → 观察输出**"的方式。在线监控模式下可以直接在软件中看到梯形图上的绿线（导通）和蓝线（不导通），非常直观。

> **仿真能发现的**：逻辑错误、变量未定义、数组越界、死循环
> **仿真发现不了的**：接线错误、干扰问题、传感器故障

### ⑥ 现场调试

这是整个流程中最耗时、最考验经验的阶段。

#### 6.1 调试前的准备

- [ ] 万用表、螺丝刀、钳子、剥线钳
- [ ] 编程电脑、编程电缆（或网线）
- [ ] 图纸（电气原理图、IO 表）
- [ ] 备用保险丝、备用模块
- [ ] 对讲机（多人配合时）

#### 6.2 调试步骤

```
第一步：不通电检查
├── 检查电源接线是否正确（L/N/PE）
├── 检查 IO 接线是否与图纸一致
├── 检查急停回路是否导通
└── 用万用表测电源端是否有短路

第二步：通电检查
├── 测量电源电压（24V ± 10%）
├── 检查 PLC 是否正常启动（RUN 灯）
├── 逐个检查输入信号（短接输入看灯亮不亮）
└── 逐个强制输出（看继电器、阀门动不动）

第三步：空载调试
├── 下载程序到 PLC
├── 手动模式测试每个动作
├── 自动模式空载运行
└── 测试急停、限位等安全功能

第四步：带载调试
├── 接上实际负载（电机、气缸等）
├── 调整参数（如变频器频率、PID 参数）
├── 全自动连续运行测试
└── 记录调试中发现的问题
```

#### 6.3 常见现场问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 输入灯不亮 | 传感器无电源/接线反 | 检查 24V 电源，确认 NPN/PNP 匹配 |
| 输出不动 | 负载电源没接/输出点烧坏 | 查负载电源，万用表测输出 |
| 信号抖动 | 干扰/传感器故障 | 加滤波时间、用屏蔽线 |
| 通信不上 | 电缆不对/参数不匹配 | XC 用专用 USB-422 电缆，核对波特率和站号 |
| 电机启动不了 | 热继电器跳了/接触器坏了 | 复位热继，查接触器线圈电压 |

##### 信捷 XC 系列常见"坑"

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| **PLC 不运行** | PLC 在 STOP 状态 | 将运行开关拨到 RUN，或 XDPPro 中点击"运行" |
| **下载不了程序** | 通信参数不对或电缆问题 | 确认使用信捷专用编程电缆，检查 COM 口设置 |
| **X/Y 地址对不上** | 混淆了八进制和十进制 | 记住 X/Y 是八进制：X7 后面是 X10，不是 X8 |
| **输出点不亮** | 晶体管输出接反/烧坏 | 晶体管输出有极性，检查是否过载或短路 |
| **双线圈问题** | 同一个 Y/M 在两处赋值 | 检查梯形图，确保每个线圈只在一个地方被驱动 |
| **脉冲输出异常** | 脉冲参数配置不对 | 检查 PLS 指令或高速脉冲输出配置是否正确 |
| **通信乱码** | 波特率/校验不一致 | 核对两端串口参数完全一致（含停止位） |

### ⑦ 验收交付

#### 7.1 功能验收

按照需求文档逐项验证，通常包括：

```
□ 手动模式各动作是否正常
□ 自动模式流程是否正确
□ 急停是否可靠停机
□ 故障报警是否能正确触发和复位
□ 通信是否稳定（上位机、HMI）
□ 连续运行 24~72 小时无异常
```

#### 7.2 交付物

- **程序源文件**（西门子 .ap14/.zap15，信捷 XC .xpj 或 .dat）
- **电气原理图**（PDF + 源文件）
- **IO 表**（信号点表）
- **操作手册**（如何开机、操作、故障处理）
- **程序注释文档**（关键逻辑说明）
- **备份**（最终版程序 + 参数文件）

#### 7.3 操作培训

- 教操作人员：如何开机/关机、如何复位报警、常见故障判断
- 教维修人员：如何查看程序状态、如何强制变量、如何监控故障

### ⑧ 运行维护

PLC 交付后不是结束，而是开始。

#### 日常维护

- 定期备份程序（每次修改后都要备份）
- 检查 PLC 运行状态（CPU 负载、扫描周期）
- 检查模块指示灯是否正常
- 保持控制柜通风、清洁

#### 常见故障处理流程

```
设备出现故障
    ↓
观察 PLC 指示灯（SF / RUN / 模块灯）
    ↓
用编程软件在线监控程序
    ↓
查看输入信号是否正常
    ↓
查看输出信号是否正常
    ↓
定位到故障点（传感器坏？执行器坏？程序逻辑？）
    ↓
处理故障 → 验证 → 记录
```

#### 版本管理建议

```
v1.0 ── 初始版本（交付验收）
 │
 ├── v1.1 ── 修复 BUG（现场发现的小问题）
 ├── v1.2 ── 优化参数（PID 参数调整）
 │
 └── v2.0 ── 新增功能（客户要求增加新功能）

每次修改都要在程序注释中写明：
  修改人、日期、修改内容
```

## 五、常见开发模式

### 5.1 从零开发（新项目）

全新设备，没有现成程序可参考。需要：
- 完整走完上述 8 个步骤
- 从第一个梯形图网络开始写起

### 5.2 模板修改（类似项目）

之前做过类似的设备，在原有程序上修改：
- 修改 IO 地址映射
- 调整工艺参数
- 增加/删减功能

> **效率最高**的方式，但要注意：模板程序的注释和文档要写清楚，否则几个月后自己都看不懂。

### 5.3 标准库开发（成熟团队）

公司建立了标准功能块库（如 FB_电机控制、FB_阀门控制、FB_PID 调节）：
- 新项目直接调用标准库
- 只需配置参数而不是重复写逻辑
- 稳定可靠，经过多次项目验证

```
示例：标准 FB_电机控制
┌───────────────────────────┐
│  FB_MotorControl          │
│                           │
│  Start ─┤              ├──▶ Running   │
│  Stop  ─┤              ├──▶ Fault     │
│  Fault ─┤   逻辑内部    ├──▶ Speed     │
│  Speed ─┤   封装好了    │              │
│                           │
└───────────────────────────┘
  使用这个 FB，只需要 3 个网络：
  "Motor1"(Start:=I0.0, Stop:=I0.1, ...);
```

## 六、一句话总结

> **写 PLC 程序只占整个开发时间的 20%，剩下的 80% 是在搞懂需求、接对线、排故障。** 程序写得再漂亮，IO 表没做对、现场线没接好，机器照样转不起来。

| 阶段 | 一句话 |
|------|--------|
| 需求分析 | 搞清楚要干啥 |
| 方案设计 | 选好 PLC（XC 哪一款？），画好图纸 |
| 硬件组态 | XDPPro 中选好型号，配置参数 |
| 程序编写 | 把工艺逻辑翻译成梯形图，注意八进制 |
| 调试监控 | XDPPro 在线监控，看绿线蓝线找问题 |
| 现场调试 | 接上线，让机器真正动起来 |
| 验收交付 | 证明机器能跑，教人会用 |
| 运行维护 | 出了问题能快速定位修复 |
